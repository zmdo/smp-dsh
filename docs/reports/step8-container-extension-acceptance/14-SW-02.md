- 结果：部分通过
- 测试时间：2026-10-20 21:20～21:31 CST
- 对象：`container-missing`（43.128.72.83）

## 前置状态

- 机器：Docker CE `26.1.1`，Compose Plugin `2.27.1`
- 控制台：Docker／Compose 均检测为已安装
- apt 源：Docker 官方 stable
- 候选版本：Docker `29.9.1`

## 步骤

1. 执行巡检，确认 Docker `26.1.1`。
2. 创建升级计划：
   ```json
   {
     "kind": "upgrade",
     "server_ids": ["78267d3e-..."],
     "versions": {
       "@smp/console-server-containers/docker-engine": "29.9.1"
     }
   }
   ```
3. 等待预检：`ready`。
4. 确认计划：
   - 时间窗口 2 小时
   - 并发 1
   - 确认 major 升级和服务影响
5. 等待执行。

## 结果

- 计划状态：`partial_failure`
- 目标结果：
  ```json
  {"error":{"code":"ssh_handshake_timeout","detail":"网络连接已建立，但 SSH 握手超时（总等待上限 30 秒）。"}}
  ```
- 机器实际版本：
  ```text
  Docker version 29.9.1
  Docker Compose version v2.27.1
  ```
- 即 Docker 已升级成功，但计划在升级后的 SSH 验证阶段超时，未确认完成。

## 问题

1. Docker 重启后 SSH 短暂不可用，30 秒握手超时不足以完成验证。
2. 计划正确标记为 `partial_failure`，没有假装成功。
3. Compose 未在本次计划中升级，仍是 `2.27.1`。
4. 缺少“升级已应用、验证超时”的自动重试或恢复确认步骤。

## 结论

升级执行链路可用，但升级后验证/恢复策略不足。需要增加重试或把“远端已变更、验证超时”作为可恢复状态处理。

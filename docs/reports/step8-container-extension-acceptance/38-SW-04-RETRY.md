# 38 SW-04：暂停后重试

- 用例：SW-04 retry
- 结果：阻塞（重试预检成功后确认被配置变更拦截）
- 测试时间：2026-10-21 03:30 CST

## 准备

四台服务器全部使用 `smp-noexec`，无 sudo，Compose 2.27.1。

批量升级 Compose 5.6.0：

- 第一台失败
- 其余 pending
- 计划进入 `paused`

证据计划：`6b61d064-5a9e-4fc5-bdf0-acea3c91306a`

## 重试步骤

1. 将失败目标 `r3` 的 SSH 用户改回 `ubuntu`（有 sudo）。
2. 对暂停计划调用 retry。
3. 新计划：`2e6ebd14-6673-47ab-ae21-34f6f41c9c24`。
4. 预检全部 `ready`。
5. 为了继续执行，又把其余目标也改回 `ubuntu`。
6. 确认重试计划。

## 结果

确认失败：

```json
{
  "code": "job_configuration_changed",
  "detail": "任务排队后服务器配置已变化，请重新发起任务"
}
```

## 原因

预检完成后，我又修改了服务器的 SSH 用户，导致配置修订变化。

系统正确拒绝执行旧预检快照。这不是 retry 无限失败，而是：

- 重试预检成功
- 但确认前又改配置
- 计划快照失效

## 结论

本轮没有验证“暂停后重试成功”，因为：

- 不能改 sudoers
- 改 SSH 用户又会改变配置修订
- 改包又会改变软件状态

要验证成功重试，需要一个**不改变服务器配置和软件状态**就能恢复的临时失败，例如短暂 SSH 故障，或可恢复的权限错误。

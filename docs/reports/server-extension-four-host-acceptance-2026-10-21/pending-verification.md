## 本轮未验证／仍保留的功能边界

| 项目 | 当前结论 | 后续验证重点 |
| --- | --- | --- |
| 不升级软件、只修复 docker 组权限 | 未验证；当前没有独立的同版本修复闭环，本轮 .98 借助真实升级完成加组 | 在已满足版本要求的服务器移除 SSH 用户的组权限，确认产品是否提供修复入口；若没有，需要另行设计，不能靠重复检测认定修复成功 |
| 组件崩溃后同一会话自动恢复 | 历史已知限制，本轮未验证或修复 | 触发错误隔离后修复／重新加载插件，检查同一会话能否恢复；不能仅以其他面板仍可用判为通过 |
| Docker 降级 | 历史未单独实测，本轮仍未验证 | 选定允许的较低版本，核对包版本锁定、服务重启、实际结果及失败后的远端状态 |
| 活动业务容器／Compose 服务在升级中的影响 | 本轮容器仅 Created 状态，没有运行工作负载 | 使用可丢弃服务验证重启、恢复及数据完整性，不推断升级无服务中断 |
| 批量升级部分失败、取消、进程重启、SSH 中断后的恢复 | 原步骤 8 有相关证据，本轮未重跑 | 用多目标计划重验暂停未开始目标、在途任务收尾及实际变更报告 |
| 全部原 167 项、终端生命周期及其余页面 | 未全量重验；仅使用本报告明确列出的界面与路径 | 需要全面发布验收时，以原清单逐项重验并记录当前代码版本 |
| 更多发行版、架构、Windows 与自定义系统 | 本轮实机仅 Ubuntu 24.04 x86_64 | 按插件声明的支持范围准备环境，不把 Ubuntu 通过外推到其他系统 |
| 大规模、长时间运行和容量 | 未进行压力／长稳测试 | 另行设定服务器数、采集频率、运行时长和资源指标 |

## 不再排查的环境项

用户已确认本轮偶发 SSH 认证超时源于本机联机不稳定，并明确要求不再处理。保留失败日志和数据库 offline 状态作为真实测试背景；它不列为本轮待修产品缺陷，也不标为稳定性测试通过。

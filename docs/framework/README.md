## 信息的使用顺序

1. 实际行为看本基线的源码、迁移与测试；每篇文档附相应入口。
2. 新需求看用户已经确认的设计，且必须确认其实施状态。设计确认不等于代码已存在。
3. `docs/design` 保留需求推导、方案和阶段记录；不能把其中全部内容当作当前 API 或部署步骤。
4. 本目录是当前交接入口，发现与新代码不符时同步更新。它不会取代用户的新指令，也不保证其他分支与本分支行为相同。

文中状态约定：“已实现”表示当前源码存在相应路径；“已确认／待实施”表示需求已确定但没有实现；“当前限制”是接手时需要知道的实际边界，不代表本次已经修复。

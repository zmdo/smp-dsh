# 登记、任务执行与升级

核对基线：`ces/develop`，`f2b8d86`，2026-10-20。

## 登记和系统识别

认证信息包含地址／端口、用户和密码／私钥引用。测试连接先由宿主读取实际凭据，通过 SSH 返回指纹和有效期 10 分钟的加密 receipt；系统识别需带 receipt，并复核认证与连接身份。

识别返回探测系统、可登记系统、适用类型及必要软件观察，不安装软件。表单 `EnrollmentPreview` 按连接修订、组、类型、系统和类型定义缓存观察；连接变化或 receipt 过期失效，迟到响应不能覆盖新选择。改变类型后可自动检查并复用有效缓存，实际安装目标仍由后端预检确定。

操作系统也可从两行目录中选择或在“其他”中手填；登记并不要求此前已经取得可执行的软件计划。服务器可以保存为尚未核验状态，但软件变更前必须通过实际系统核验，声明与探测冲突不能靠表单选择绕过。

保存服务器是持久配置操作。启用自动安装或要求保存后检查时会排队；自动安装是对缺失必要软件准备独立计划的许可，不授权任意升级、替换或降级。

## 队列和执行

| 项目 | 当前实现 |
| --- | --- |
| 调度位置 | 控制端 dsh 进程，非远端心跳／ping |
| worker 总并发 | 4 |
| 领取检查 | 约每 400ms pump，受数据库锁与计划窗口限制 |
| 到期巡检／升级调度 | 约每 5 秒检查到期条件，业务间隔另由配置控制 |
| 每服务器执行互斥 | 行锁、活动任务约束与领取检查 |
| 数据库租约 | 60 秒，每 15 秒续租，递增 fence 保护写入 |
| 任务用途 | `inspect`、`detect_updates`、`apply_plan` |
| 变更授权 | 计划／目标快照、具体版本、配置／环境／定义修订和维护窗口 |

任务保留排队、运行、恢复、成功、失败、阻塞、取消等状态；数据库还允许领取阶段。不要仅根据一个 state 字符串判断远端是否已经修改软件，应结合 phase、mutation_phase 和远端日志。

## 只读巡检

周期巡检读取 SSH、系统、必要软件和当前内置容器观察。`dueInspects()` 当前只选择连接状态 online 且到期、没有待执行巡检的服务器；不构成对所有离线服务器不断重连的心跳系统。失联后可能需要显式测试／其他任务恢复在线。

当前 worker 对已验证的非 Windows 系统尝试容器读取，并不是只在勾选“安装必要软件”或选择普通类型时才走这条路径。Docker 命令不存在可记为不适用；已有 Docker 但权限／清单失败会进入失败报告。

周期成功执行记录仍留在数据库，但普通任务列表不逐条显示；完成的 UTC 小时存在成功时展示聚合报告，失败记录单独可查。自动升级检测成功也有专门的列表隐藏规则。查询规则看 task-history repository，不能只在前端隐藏。

指标采集是独立控制端 SSH 采样，默认每秒；当前使用 Linux `/proc` 等信息，要求当前系统已核验且非 Windows。连接缓存、重试与忙碌状态由该次 apply 拥有，不能用指标错误直接覆盖软件任务事实。

## 初装和替换

只读预检观察软件、查询现有源候选、解析精确包与依赖。初装缺失软件形成独立 prepare 计划；已有软件冲突要求明确替换确认，未知不能被当作缺失直接安装。

用户确认的计划冻结产品版本、包版本（含 epoch／发行修订）、来源、校验值、依赖、实际原状和修订。执行前再检查，目标漂移不能静默追随最新版本。当前初装计划有 15 分钟可开始窗口；过窗不补执行。

远端使用 root 所有的 `/var/lib/smp-server-management`、操作 ID、主机 flock 和逐软件日志。SSH 断开不等于安装未开始，也不等于已失败；重复同一操作 ID 不重复执行，未知结果进入 recovering。

## 移动分组与改类型

普通编辑 PATCH 拒绝直接改变绑定。移动弹窗选择目标组／类型和安装偏好，默认保留仍适用类型，否则预选目标默认类型；宿主重新检查。

预检展示保留、安装、替换／可能降级和依赖变化，拒绝替换就取消此次移动。操作成功并验证后才在完成事务提交新组／类型／策略；失败保持原归属，但必须报告远端已经发生的变化，不能宣称远端回滚。

转为空置不自动卸载原有软件。当前运行／恢复中的任务会阻止冲突的配置变更或删除。

## 自动检测与批量升级

自动检测按软件默认关闭，仅执行 detect／候选／解析，不修改软件。用户范围只收紧类型范围；完整固定版本或达到完整范围上限不可继续产生更高候选，当前软件源已是最新则仍可保持检测偏好。

拒绝针对一台服务器一个软件的精确目标，可撤销，更高目标继续检测；推迟只延后提醒。所有实际升级均需用户明确创建并确认即时或预约计划，不能把检测开关当作授权执行。

共同版本预检固定服务器清单，一次最多 500 台，所选软件必须在全部目标的 OS／架构／范围／依赖上可安装同一产品版本。不同机器的精确包可不同，但不能静默跳过不符合者。

维护计划记录 IANA 时区、可开始窗口和并发，默认串行，最大 4。任一失败暂停未开始目标，已开始任务有序收尾；暂停不强杀包管理器。错过窗口不在恢复后自动补升级，重试／改期重新预检并确认，成功项不重跑。

关闭自动检测不等于取消已确认计划。翻译和普通指标刷新不改变计划授权；配置、实际软件、范围、精确包或定义改变会阻塞并要求重新确认。

## 重启与未知结果

控制端恢复时可领取过期执行并依据远端日志核对，不能按旧文档把所有 running 一律标失败。已接受的远端操作可在提供者撤回后依靠操作日志恢复，但不能因此接受新的插件脚本执行。

无法确认远端结果时保留恢复／互斥状态，当前尚无人工强制解除未知操作的完整入口。新建 operation ID、直接改表成失败或手动重跑安装都可能绕过幂等与互斥。

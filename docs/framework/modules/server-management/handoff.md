# 服务器管理交接状态与下一步

核对基线：`ces/develop`，`f2b8d86`，2026-10-20。

## 当前已实现

类型／系统组与国际化、操作系统登记和核验、认证测试与识别缓存、实例状态和接口分页、必要软件版本范围、移组预检／冲突确认、只读升级检测、升级建议处理、批量维护计划与恢复均有当前代码路径。

上一轮按业务拆分前后端、SQL、模型及协议的重构也已完成；不要把后续详情工作区当作仍需继续的旧目录重构。

## 已确认但未实现

下列需求已形成设计，八步均尚未开始：

| 需求 | 已确认目标 |
| --- | --- |
| 单台服务器详情局部侧栏 | 服务器详情、任务报告、终端、配置及插件入口 |
| 任务报告拆出 | 独立面板，保留查询、分页和小时巡检汇总 |
| 终端会话 | 同一服务器内切换面板保持；退出详情、换服务器或主动断开时关闭 |
| 面板扩展 | 其他插件可按稳定类型键显示仅该类型适用的侧栏选项／面板 |
| 配置扩展 | 自定义配置栏目、宿主校验、持久化和修订冲突处理 |
| 容器类型 | 普通类型更名为“容器服务器”，由独立正式插件提供 |
| 公共类型目录 | 用户组、未分组及未限定类型的系统组可选；默认仍为空置 |
| 容器清单采集 | 默认开启，可关闭；关闭后手动刷新和必要软件检测继续保留 |

当前 `builtin/general`、容器表和 Docker 配方仍属于核心。不能先删核心实现再假设新插件已经加载，也不能两边同时开启同一巡检。

## 执行入口

需求细节：[详情扩展与容器插件设计](../../../design/server-management/detail-extensions-and-container-plugin.md)。

具体步骤：[八步实施计划](../../../design/server-management/detail-extensions-implementation-plan.md)。**下一步为步骤 1：详情工作区与独立任务报告。** 原计划保留用于逐步更新实施记录；本页只总结当前交接状态。

顺序为：基础工作区 → 终端所有权 → 内置配置 → 公共类型与扩展契约 → 自定义面板／配置 → 巡检扩展 → 容器迁出与数据切换 → 完整验收。

拟议名称 `publicTypes`、`registerServerExtensions()`、详情／配置子槽、扩展观察与配置表都不是当前可调用 API。实施前按计划定稿版本校验和公开导出，不静默给当前契约新增无效字段。

## 其他未覆盖边界

- 自定义操作系统贡献、Windows／PowerShell 软件配方和运行时新增软件依赖目前被拒绝，不在“接口已有类型”的意义上视作完成。
- 对话会话的服务器目录工具／远程 shell 仍是历史待实现设计；不能照旧方案直接更新组 ID，绕过现在的软件／类型预检。
- 未提供人工强制解除未知远端操作的完整流程；远端变更可能部分成功，必须保留事实。
- 列表完整 SQL 下推优化未实施，且用户此前要求暂不做；当前数据持久化不受此限制影响。

## 接手时保留的约束

当前数据可能已有测试服务器、密钥、观察和历史。早期允许破坏兼容不等于如今数据库为空；容器插件切换按计划检查实际记录、进行中操作和键转换。保留旧执行历史身份，旧未开始计划重新预检，不保留长期旧键别名。

只修改文档或 UI 时不顺手安装／升级真实服务器软件，不清空无关数据。临时验证插件只由测试装载，正式 CES 只显式加载需要的正式插件。分支操作、提交和推送按具体任务指令执行。

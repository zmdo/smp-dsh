# 会话目录变更（session-catalog）

状态：待实现。本文记录会话如何创建分组、把服务器移入分组，以及修改服务器名称。看见服务器和执行命令仍以 [session-shell.md](session-shell.md) 为准。页面、登记和分组规则仍以 [design.md](design.md) 为准。

运行版本钉在 `dsh` `0.2.1-alpha.5`。插件写法以 `.agents/skills/dsh-plugin/` 为准。

## 1. 要解决的事

会话已经能看见开放给它的服务器。分组和名称仍只能在页面上改。

会话可以做三件事：新建分组、把一台可视的服务器移到某个分组、修改一台可视的服务器的名称。每一件在写入之前都要人批准。未批准就不写库。

这三件事不登录服务器，也不改地址、端口、登录方式和会话权限。

## 2. 结论

| 事项 | 决定 |
| --- | --- |
| 插件 | 仍是 `@smp/console-server-management` |
| 宿主 | `inject` 再加上 `approval` |
| 批准 | 写入前调用 `ctx.approval.request`。只有 `allowed-once` 才写库 |
| 一次调用 | 一件事，一次批准。不在一次调用里改多台服务器 |
| 谁能被改 | `session_access` 为 `visible` 或 `operate` 的服务器。`none` 不能改名，也不能移动 |
| 新建分组 | 不要求某台服务器可视。分组名在全部会话里都能用 |
| 工具 | `server_group_list`、`server_group_create`、`server_move`、`server_rename` |
| 未分组 | 移动时用空分组表示「未分组」。不能创建名为「未分组」的分组 |
| 名称 | 去掉首尾空白后 1 到 80 个字符。分组名全库唯一。服务器名允许重复 |
| 这一步不做 | 不删除分组。不改地址、端口、用户、认证、密钥、区域、组件和 `session_access`。不用 `ask_user_question` 代替批准。不另做批准页面 |

## 3. 批准

工具先检查参数和当前库里的行。检查没过就直接失败，不询问。

检查通过后，用这次工具调用的 `callId` 调用 `ctx.approval.request`。理由里写明要发生的事，例如「将「db-1」移入「生产」」或「将「db-1」改名为「记账库」」。参数里已经有服务器现名、新名和分组名，批准提示贴在这次工具调用上。

然后按结果处理：

| 结果 | 行为 |
| --- | --- |
| `allowed-once` | 再读一遍库。要改的行仍和询问时一致，才写入 |
| `rejected` | 不写。告诉模型未获批准 |
| `cancelled` | 不写。告诉模型已取消 |
| `unavailable` | 不写。告诉模型现在无法询问批准 |

会话的批准策略是 `never` 时，服务直接返回 `rejected`，不写库。没有应答者时同样不写。人在会话里已有的批准提示上选择允许或拒绝。

批准之后、写入之前，行必须仍满足当时的条件：服务器仍可视，名称仍是询问时的名称，分组仍是询问时的分组。有任何一条不符，就不写，并说明记录已经变了，需要重新发起。

## 4. 工具

`server_group_list` 没有参数，也不需要批准。返回全部分组的编号和名称，按名称排序，另加一条空编号的「未分组」。每个分组的 `serverCount` 只数 `visible` 和 `operate` 的服务器，不泄露不可视服务器的名称和数量。

`server_list` 的每一行带有 `groupId` 和 `groupName`，见 [session-shell.md](session-shell.md)。未分组时这两项为空。

`server_group_create` 的参数是 `name`。去掉首尾空白后为空、超过 80 个字符，或名字是「未分组」时拒绝。重名时拒绝，不插入第二行。批准通过后插入 `server_groups`，返回编号和名称。

`server_move` 的参数：

| 参数 | 约束 |
| --- | --- |
| `server` | 必填。可视服务器的编号 |
| `group` | 分组编号。空表示移入「未分组」 |

服务器不可视、编号不存在，或分组编号对不上已有分组时，在询问前拒绝。移入当前所在的分组也拒绝，不询问。批准通过后只更新 `group_id` 和 `updated_at`。

`server_rename` 的参数：

| 参数 | 约束 |
| --- | --- |
| `server` | 必填。可视服务器的编号 |
| `name` | 必填。去掉首尾空白后 1 到 80 个字符 |

新名和现名相同时拒绝，不询问。批准通过后只更新 `name` 和 `updated_at`。

三件写入都观察取消信号。询问还没返回时取消，按 `cancelled` 处理，不写库。

## 5. 页面

不新增页面。人在「服务器」页上的新建分组、改分组和改名保持原样，那些操作不走这次批准。

会话写成的分组和名称，下一次列表刷新就能看到。

## 6. 测试

用 `node:test`。不打开真实的批准界面。用替身返回四种结果。

- 参数不合法，或服务器不可视时，不调用批准，也不写库。
- 返回 `rejected`、`cancelled`、`unavailable` 时不写库。
- `allowed-once` 之后行已经被改过时不写库。
- 创建分组在批准后插入一行，并返回编号。重名和「未分组」不插入。
- 移动只改 `group_id`。空分组把服务器放回未分组。
- 改名只改 `name`。地址、认证和 `session_access` 不变。
- 分组列表的 `serverCount` 不含 `none` 的服务器，结果里没有这些服务器的名称。

# 服务器管理结构整理：公共边界、前端与后端分层

日期：2026-10-20。开发分支：`ces/refactor-sm`。

本轮已完成前三步：整理公共契约、错误和数据库基础类型，解除运行时循环依赖；拆分服务器与升级管理两个大页面；将后端 HTTP、业务工作流和 SQL 按职责分离。第 4 步（执行器处理器、插件定义与脚本管理的进一步整理）尚未执行。

`shared` 仅引用自身和双语资源，不依赖客户端、宿主实现或 Node 内置模块。客户端仅引用自身、`shared`、React 和控制台组件库，包含 type-only 导入在内均受约束。宿主可引用公共模型；`Db` 接口与 HTTP 错误独立于具体存储。

取消 `store.ts` 对队列函数和 `JobRecord` 的转导出，调用方直接引用 `job-store.ts`。抽走 `HttpError` 后，变更流程不再通过存储模块获取异常类型。此前两组运行时循环均消除：

```text
i18n → definitions → operating-systems → i18n
store → job-store → changes → store
```

`ServerError` 保存稳定错误码和参数，其 `message` 使用错误码。翻译只在展示、HTTP 错误响应和需要保存人类可读诊断的边界执行，保持原有错误响应和任务诊断含义。错误码表与中英文资源通过测试核对。

操作系统选择器、匹配范围、登记模型和基础检测事实只有一份公共定义。配方协议需要原始探测字段时使用 `ProbedOs`，不再通过两份同名 `DetectedOs` 表达不同要求。页面的计划、软件策略和响应类型不再从后端执行实现文件获取。

## 前端状态与请求的归属

- `client.tsx` 单次 `apply` 创建共享页面状态，卸载时清理；顶部导航与升级内容使用同一份状态，不引入模块级单例。
- `ServersPage` 管理页面目的地和列表视图状态；列表、表单和详情各自的 Hook 管理请求及局部工作流。表单继续保留认证修订、连接回执、识别缓存、并发去重及迟到响应隔离。
- `UpgradesPage` 管理三个 Tab 和计划详情的装配。建议工作流 Hook 持有筛选、选择、共同版本、反馈与操作命令；建议视图、批量面板和推迟弹窗只负责展示和调用命令。
- 建议 Hook 在同一升级页面内跨 Tab 保留输入和选择，只在建议视图激活时轮询。计划与记录各自读取自身数据，不再顺带请求建议所需的库存与分组。
- 计划和记录共用挂载实例拥有的轮询 Hook；切换查询或卸载会取消在途请求和后续定时器。列表、详情、终端及登记预览继续保持各自已有的清理约束。
- 内容标题继续跟随顶部 Tab；从实例／详情进入升级建议、从记录查看计划、返回列表时保留筛选等导航行为沿用现有规则。

## 后端职责与事务边界（第 3 步）

`index.ts` 保留插件实例装配、公共导出和后台循环。HTTP 注册迁到 `host/http/routes.ts`，仍逐一向原有 effect 交出注销函数，保持逆序清理关系。原有 URL、响应状态、错误码和认证要求不变，HTTP 适配器负责解析请求、调用工作流、发送响应，不执行 SQL。列表和任务的 URL 查询参数转换为独立的类型化查询模型后交给业务层。

`records.ts` 不再作为服务器、分组、密钥和任务的集中入口；`change-routes.ts` 中的建议决策、共同版本计算与计划重试也迁入各自业务服务。删除这些旧文件并更新调用方，不留转导出的兼容入口。服务不依赖 `node:http` 或 HTTP 模块；repository 不依赖服务，也不取得独立连接、开启或结束事务。

`host/db.ts` 统一连接取得、提交、回滚和释放。事务由工作流明确选择，repository 接收调用方传入的同一连接：

| 操作 | 原子边界与保持的约束 |
| --- | --- |
| 登记 | 目录锁下写入服务器、运行状态、软件策略和初始任务；任一失败全部回滚 |
| 编辑 | 目录锁和服务器行锁下读取旧配置、计算修订、写入配置／策略、作废旧建议、重置状态并入队；临界配置仍检查运行中任务 |
| 用户分组删除 | 锁定分组和成员，校验系统分组保护、类型与 OS 后解绑和删除 |
| 服务器删除 | 行锁和忙状态检查后取消待执行任务／目标并删除；保留不可变历史身份 |
| 创建／确认计划 | 同一事务写计划、目标和任务；确认仍验证预检摘要、修订、维护窗口与影响确认 |
| 预检／移动完成 | 预检快照在 worker 所有权校验事务内保存；预检状态推进、移动绑定与策略更新在任务完成事务内提交；repository 不独立提交，迟到 worker 不能覆盖取消结果 |
| 建议拒绝／恢复／推迟 | 在锁定建议的事务内修改本次版本决策或提醒时间 |
| 实例列表 | 保留 repeatable read 只读事务，同一快照读取分组、计数、运行事实、软件事实、策略和升级建议，再聚合状态、筛选、排序和分页 |

配置更新向 repository 传入类型化 `ServerPatch`，业务层不再拼接 SQL 列名和占位符。登记和编辑的插件类型租约仍持有到工作流提交／回滚后释放；临时 SSH 识别仍只读且不写服务器事实。

新增架构约束覆盖 HTTP／服务无直接 SQL、存储不依赖服务或控制事务，以及宿主／客户端无运行时循环。新增数据库故障回归测试在配置和策略写入后注入任务入队失败，验证登记及编辑均完整回滚；新增真实本地 HTTP 测试覆盖认证优先、400／401／404／405／422／500 映射、内部异常隐藏及路由卸载。

此次仅调整结构，无数据库结构更新。后台任务执行器、队列 claim／fencing、远端监督器、定义注册表和安装脚本仍保留既有实现，后续第 4 步再整理其职责。

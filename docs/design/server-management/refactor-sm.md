# 服务器管理结构整理：公共边界与前端拆分

日期：2026-10-20。开发分支：`ces/refactor-sm`。

本轮完成结构调整的前两步：整理公共契约、错误和数据库基础类型，解除运行时循环依赖；拆分服务器与升级管理两个大页面。后端路由／业务／SQL 拆分以及执行器处理器拆分留待后续阶段。

## 目录和依赖

```text
src/
  index.ts                         宿主装配与公共导出
  client.tsx                       客户端槽登记与实例状态所有权
  shared/
    contracts.ts                   插件注册与配方协议
    api.ts                         页面使用的 HTTP 数据结构
    changes.ts                     预检计划与变更请求数据
    errors.ts                      独立错误码、错误对象和边界解析
    i18n.ts                        翻译、格式化、错误显示与响应封装
    operating-system-types.ts      OS 公共模型；ProbedOs 扩展原始探测字段
    operating-systems.ts            OS 目录及匹配规则
    versions.ts                    版本约束和比较
    policies.ts                    软件策略数据
    definitions.ts                 类型和软件视图、适用性规则
    server-list-contract.ts         列表和统一状态数据
  host/
    db.ts                          Db／DbClient 基础接口
    http/error.ts                  带 HTTP 状态的错误
  client/
    shared/                        API、语言订阅、实例页面状态、样式和资源格式化
    servers/
      ServersPage.tsx              列表／表单／详情／终端的装配
      list/                       列表视图与查询、分组操作 Hook
      form/                       表单视图、认证／系统区域、登记工作流 Hook 和识别缓存
      detail/                     详情视图及其 Hook、移组弹窗、任务历史
      terminal/                   终端视图与连接生命周期
      components/                 软件、安装策略及状态组件
    keys/                         服务器密钥页面
    changes/                      登记安装、移组与升级共用的计划详情
    upgrades/
      UpgradesPage.tsx            Tab 内容和计划详情装配
      UpgradesNavigation.tsx      顶部导航
      suggestions/                建议视图、筛选、批量安排、推迟及工作流 Hook
      plans/                      计划列表
      records/                    执行记录
```

`shared` 仅引用自身和双语资源，不依赖客户端、宿主实现或 Node 内置模块。客户端仅引用自身、`shared`、React 和控制台组件库，包含 type-only 导入在内均受约束。宿主可引用公共模型；`Db` 接口与 HTTP 错误独立于具体存储。

取消 `store.ts` 对队列函数和 `JobRecord` 的转导出，调用方直接引用 `job-store.ts`。抽走 `HttpError` 后，变更流程不再通过存储模块获取异常类型。此前两组运行时循环均消除：

```text
i18n → definitions → operating-systems → i18n
store → job-store → changes → store
```

`ServerError` 保存稳定错误码和参数，其 `message` 使用错误码。翻译只在展示、HTTP 错误响应和需要保存人类可读诊断的边界执行，保持原有错误响应和任务诊断含义。错误码表与中英文资源通过测试核对。

操作系统选择器、匹配范围、登记模型和基础检测事实只有一份公共定义。配方协议需要原始探测字段时使用 `ProbedOs`，不再通过两份同名 `DetectedOs` 表达不同要求。页面的计划、软件策略和响应类型不再从后端执行实现文件获取。

## 前端状态与请求的归属

- `client.tsx` 单次 `apply` 创建共享页面状态，卸载时清理；顶部导航与升级内容使用同一份状态，不引入模块级单例。
- `ServersPage` 管理页面目的地和列表视图状态；列表、表单和详情各自的 Hook 管理请求及局部工作流。表单继续保留认证修订、连接回执、识别缓存、并发去重及迟到响应隔离。
- `UpgradesPage` 管理三个 Tab 和计划详情的装配。建议工作流 Hook 持有筛选、选择、共同版本、反馈与操作命令；建议视图、批量面板和推迟弹窗只负责展示和调用命令。
- 建议 Hook 在同一升级页面内跨 Tab 保留输入和选择，只在建议视图激活时轮询。计划与记录各自读取自身数据，不再顺带请求建议所需的库存与分组。
- 计划和记录共用挂载实例拥有的轮询 Hook；切换查询或卸载会取消在途请求和后续定时器。列表、详情、终端及登记预览继续保持各自已有的清理约束。
- 内容标题继续跟随顶部 Tab；从实例／详情进入升级建议、从记录查看计划、返回列表时保留筛选等导航行为沿用现有规则。

## 验证方式

新增架构测试检查前端／公共层依赖边界，并从宿主与客户端构建依赖图中检测运行时循环。现有 PostgreSQL、配方协议、远端日志恢复、SSH 认证、登记识别缓存和国际化测试继续运行。

严格类型检查额外启用 `noUnusedLocals`；使用全仓构建与浏览器验证登记表单、密钥显示、列表状态及顶部 Tab／内容标题。测试在隔离 schema 和本地 SSH／包管理器替身中运行，不通过此次重构改变数据库结构或执行真实服务器的软件升级。

本轮验证结果：服务器管理 99 项全部通过；全仓 235 项中 232 项通过、3 项既有环境相关测试跳过、0 失败。严格类型检查、全仓构建和 `git diff --check` 均通过。本地 CES 已重启使用构建产物，浏览器核对了登记表单、已有密钥隐藏、OS／类型联动、详情与编辑、移组弹窗、密钥页面、列表筛选保持，以及升级三个 Tab 的内容、标题和筛选保持。

页面装配入口规模：`ServersPage.tsx` 从 1708 行降至 105 行，`UpgradesPage.tsx` 从 723 行降至 64 行；状态、请求及业务视图已分别归属到对应业务目录。减少入口代码量不代表删减业务，表单缓存、任务互斥、失败恢复等仍由原有测试覆盖。

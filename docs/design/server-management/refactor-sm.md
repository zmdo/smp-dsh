# 服务器管理结构整理：公共边界、前后端分层与后台执行

日期：2026-10-20。开发分支：`ces/refactor-sm`。

本轮四步结构调整已完成：整理公共契约与基础类型、解除运行时循环；拆分服务器与升级页面；分离 HTTP／业务／SQL；整理后台任务处理器、队列、定义注册与脚本管理。此次完成的是结构重构，具体功能需求的完成范围仍以各需求文档为准。

`shared` 仅引用自身和双语资源，不依赖客户端、宿主实现或 Node 内置模块。客户端仅引用自身、`shared`、React 和控制台组件库，包含 type-only 导入在内均受约束。宿主可引用公共模型；`Db` 接口与 HTTP 错误独立于具体存储。

第 1 步取消了 `store.ts` 对队列函数和 `JobRecord` 的转导出；第 4 步进一步删除这些旧入口，调用方直接引用 `host/execution` 的模型、队列、所有权与完成模块。抽走 `HttpError` 后，变更流程不再通过存储模块获取异常类型。此前两组运行时循环均消除：

```text
i18n → definitions → operating-systems → i18n
store → job-store → changes → store
```

`ServerError` 保存稳定错误码和参数，其 `message` 使用错误码。翻译只在展示、HTTP 错误响应和需要保存人类可读诊断的边界执行，保持原有错误响应和任务诊断含义。错误码表与中英文资源通过测试核对。

操作系统选择器、匹配范围、登记模型和基础检测事实只有一份公共定义。配方协议需要原始探测字段时使用 `ProbedOs`，不再通过两份同名 `DetectedOs` 表达不同要求。页面的计划、软件策略和响应类型不再从后端执行实现文件获取。

## 前端状态与请求的归属

- `client.tsx` 单次 `apply` 创建共享页面状态，卸载时清理；顶部导航与升级内容使用同一份状态，不引入模块级单例。
- `ServersPage` 管理页面目的地和列表视图状态；列表、表单和详情各自的 Hook 管理请求及局部工作流。表单继续保留认证修订、连接回执、识别缓存、并发去重及迟到响应隔离。
- `UpgradesPage` 管理三个 Tab 和计划详情的装配。建议工作流 Hook 持有筛选、选择、共同版本、反馈与操作命令；建议视图、批量面板和推迟弹窗只负责展示和调用命令。
- 建议 Hook 在同一升级页面内跨 Tab 保留输入和选择，只在建议视图激活时轮询。计划与记录各自读取自身数据，不再顺带请求建议所需的库存与分组。
- 计划和记录共用挂载实例拥有的轮询 Hook；切换查询或卸载会取消在途请求和后续定时器。列表、详情、终端及登记预览继续保持各自已有的清理约束。
- 内容标题继续跟随顶部 Tab；从实例／详情进入升级建议、从记录查看计划、返回列表时保留筛选等导航行为沿用现有规则。

## 后端职责与事务边界（第 3 步）

第 3 步时 `index.ts` 保留插件实例装配、公共导出和后台循环；第 4 步已将循环移到 `host/execution/runtime.ts`。HTTP 注册迁到 `host/http/routes.ts`，仍逐一向原有 effect 交出注销函数，保持逆序清理关系。原有 URL、响应状态、错误码和认证要求不变，HTTP 适配器负责解析请求、调用工作流、发送响应，不执行 SQL。列表和任务的 URL 查询参数转换为独立的类型化查询模型后交给业务层。

`records.ts` 不再作为服务器、分组、密钥和任务的集中入口；`change-routes.ts` 中的建议决策、共同版本计算与计划重试也迁入各自业务服务。删除这些旧文件并更新调用方，不留转导出的兼容入口。服务不依赖 `node:http` 或 HTTP 模块；repository 不依赖服务，也不取得独立连接、开启或结束事务。

`host/db.ts` 统一连接取得、提交、回滚和释放。事务由工作流明确选择，repository 接收调用方传入的同一连接：

| 操作 | 原子边界与保持的约束 |
| --- | --- |
| 登记 | 目录锁下写入服务器、运行状态、软件策略和初始任务；任一失败全部回滚 |
| 编辑 | 目录锁和服务器行锁下读取旧配置、计算修订、写入配置／策略、作废旧建议、重置状态并入队；临界配置仍检查运行中任务 |
| 用户分组删除 | 锁定分组和成员，校验系统分组保护、类型与 OS 后解绑和删除 |
| 服务器删除 | 行锁和忙状态检查后取消待执行任务／目标并删除；保留不可变历史身份 |
| 创建／确认计划 | 同一事务写计划、目标和任务；确认仍验证预检摘要、修订、维护窗口与影响确认 |
| 预检／移动完成 | 预检快照在 worker 所有权校验事务内保存；预检状态推进、移动绑定与策略更新在任务完成事务内提交；repository 不独立提交，迟到 worker 不能覆盖取消结果 |
| 建议拒绝／恢复／推迟 | 在锁定建议的事务内修改本次版本决策或提醒时间 |
| 实例列表 | 保留 repeatable read 只读事务，同一快照读取分组、计数、运行事实、软件事实、策略和升级建议，再聚合状态、筛选、排序和分页 |

配置更新向 repository 传入类型化 `ServerPatch`，业务层不再拼接 SQL 列名和占位符。登记和编辑的插件类型租约仍持有到工作流提交／回滚后释放；临时 SSH 识别仍只读且不写服务器事实。

新增架构约束覆盖 HTTP／服务无直接 SQL、存储不依赖服务或控制事务，以及宿主／客户端无运行时循环。新增数据库故障回归测试在配置和策略写入后注入任务入队失败，验证登记及编辑均完整回滚；新增真实本地 HTTP 测试覆盖认证优先、400／401／404／405／422／500 映射、内部异常隐藏及路由卸载。

此次仅调整结构，无数据库结构更新。第 3 步未改动后台任务执行器、claim／fencing、远端监督器、定义注册表和安装脚本的职责；第 4 步的进一步拆分见下节。

## 后台执行、定义与脚本（第 4 步）

`src` 顶层现在仅保留宿主入口、客户端入口和样式声明。原来的 `runner.ts`、`job-store.ts`、`store.ts`、`registry.ts`、`upgrades.ts` 等实现按职责移入 `host`，更新全部内部调用与测试，不保留旧路径的转导出文件。

### 后台任务

- `runtime` 拥有领取和维护定时器及所有已接收工作的 Promise；停止时先停止调度，再等领取／维护循环及任务完成，保持最后一次数据库写入期间依赖仍可用。
- `worker` 拥有单任务的 SSH 会话、心跳和定义租约，完成／失败后停止并等待心跳、关闭会话、释放租约。通过闭合任务类型分发到巡检、检测升级、预检和执行计划处理器，共享上下文只传入本次执行所需的服务与事实。
- 已开始的操作在普通探测和定义解析前进入恢复通道。恢复只使用已确认计划和远端日志，贡献插件已卸载时仍可核对；不明确的结果保持恢复状态和服务器锁，不自动重放。
- 所有权事务仍同时锁定匹配 worker／fence／未过期租约的任务与服务器。入队去重、`skip locked` 领取、每台服务器互斥、计划并发和维护窗口判断保留原有条件。
- `completion` 在同一所有权事务内完成任务、小时报告、预检推进、移动绑定／策略及父计划状态汇总。绑定提交继续使用 savepoint；绑定失败回滚该部分并保留远端实际结果。批量中失败仍暂停未开始的目标，已经开始的目标有序结束。
- 自动安装计划的生成与已确认计划准入独立到执行计划模块，修订、摘要、冻结目标及影响确认的检查不变。

### 定义与脚本

`DefinitionRegistry` 保留单次插件实例拥有的注册队列、已发布贡献、租约、关闭状态和等待清理；校验／加载、跨贡献解析、持久化分别有明确模块。注册只有在完整校验、跨插件引用解析和系统分组事务都成功后才发布。卸载先使贡献不可用，再等待直接和间接使用它的租约释放；已接收的脚本和恢复日志不会因贡献撤回而失效。

脚本文件读取／边界校验、冻结内容、命令引用、JSON 协议校验、稳定摘要与精确软件计划分别独立。内置 apt 配方和远端监督器脚本保留原始内容：已逐字比较重构前后脚本，并比较内置组件修订，均无变化，避免纯目录移动使已有计划失效。

### 数据库归属

PostgreSQL 连接池、迁移执行和表结构仍由 `plugins/database` 管理。服务器管理全部业务 SQL 现在位于 `host` 下各业务的 `*repository.ts`；通用事务、只读快照、目录锁和 savepoint 位于 `host/db.ts`。HTTP、任务处理器、定义解析与业务服务不直接执行 SQL。

后台 SQL 按队列／执行结果、检测调度、服务器凭据、观测事实、指标和系统分组分别归属，不再集中在 `store.ts` 或与执行器混写。repository 继续接收调用方连接，不自行取得连接或结束事务。

新增回归测试覆盖后台停止时仍等待迟到的 SSH 连接和最终持久化、脚本读取后原文件变更不影响已接受内容、路径／大小／超时边界；扩展架构约束覆盖全部宿主 SQL 的归属，以及配方／定义解析对存储和任务执行的独立性。现有并发领取、过期 fence、卸载、恢复、移动失败、批量暂停和维护窗口测试继续使用隔离 PostgreSQL schema 和远端替身运行。

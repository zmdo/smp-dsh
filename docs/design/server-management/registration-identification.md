# 服务器登记：认证测试与系统信息识别

状态：2026-10-19 已确认交互并接入实现。本文补充 [基础界面](design.md) 和 [操作系统规则](operating-systems.md)，适用于登记与编辑表单。

## 页面布局

名称、分组、区域放在两个信息框之外。其下按顺序显示：

| 信息框 | 字段与展示 | 框底按钮 |
| --- | --- | --- |
| 服务器认证信息 | 服务器地址与端口同一行，用户独占一行；认证方式、已有密钥或新私钥、口令 | 测试连接 |
| 服务器系统信息 | 操作系统、系统版本／其他系统名称、服务器类型、实际架构、必要软件表格及安装选择 | 识别系统信息，绿色，初始禁用 |

已有密钥被选中时隐藏「新密钥名称」「粘贴私钥」；选择「不选择」后恢复输入。选中的已有密钥优先于隐藏的私钥草稿，不能因草稿残留创建新密钥。密钥在宿主解密使用，不回传到浏览器。编辑密码认证的服务器时，连接地址、端口、用户未改变可留空使用已保存口令；这些字段改变后需要重新填写口令。

系统大类选择的显示标签为「操作系统」，下一行为「系统版本」；「其他」仍允许手填名称与版本。类型放在系统信息框内，由分组与系统范围筛选。

「必要软件」标题使用较小字号，区域有边框。内部用表格列出当前类型的全部必要软件，而非列举服务器所有软件包：软件、已安装版本、状态。每项状态区分已安装、未安装、未检测／检测失败。安装版本来自远端检测，不把版本范围或安装候选当成已装版本。旧版本事实若保留，必须标为「上次已知版本」。空置类型显示「无需安装必要软件」。

## 操作流程与失效规则

1. 填写认证信息，点击「测试连接」。支持已保存密钥、粘贴的新私钥、新口令，以及满足上述限制的已保存口令。
2. 测试成功展示主机指纹，启用绿色「识别系统信息」。失败时保持禁用，仍允许手动填写系统信息。
3. 点击识别后重新建立 SSH，核对测试时的主机指纹，只读探测操作系统、版本、架构，并按适用的当前类型检测必要软件与实际版本；不运行安装、候选解析、替换或升级入口。
4. 将识别到的系统填入原有选择框；目录中未包含的系统／版本转入「其他」文本输入，不猜成相近的已支持系统。保留兼容的原类型，否则使用目标分组的适用默认类型，再无默认时选择适用类型。Windows 及其他系统仍遵守已有安装支持边界。
5. 部分软件检测失败时保留已识别系统及其他软件的实际版本，把失败项标为未知，不能当成未安装。空置类型不执行 Docker／Compose 检测。
6. 地址、端口、用户、认证方式或实际凭据改变后，测试成功状态立即失效，清空当前表单缓存，识别按钮重新禁用；原请求即使稍后返回也不能填入新表单。名称、区域改变不使连接失效。分组、类型或系统选择改变时，只能展示与新选择匹配的缓存；没有对应缓存则显示未检测。切换分组／类型会按下述规则自动检测。
7. 系统字段保留手动选择与更正。测试／识别不是保存的强制前提；可以先保存为待验证，后续软件变更必须经宿主实际核对系统、类型及软件状态。识别不会自行打开自动安装开关。

表单识别结果是临时预览，不直接写入服务器、密钥或软件观察表。识别后保存会排入一次普通只读核对，让宿主采集并持久化事实；不信任浏览器提交的版本信息。已明确选择补齐缺失软件时，仍按既有独立准备／安装计划执行，并重新验证，不能由识别成功直接授权替换或升级。

## 类型切换与表单缓存

- 用户选择不同服务器类型后，认证信息完整且目标类型可用时自动检测该类型。切换分组也采用相同规则；页面初次选择默认类型和识别后的兼容类型回退不递归触发自动检测。没有有效连接凭证时先自动测试连接，有效凭证存在时直接识别系统和该类型的必要软件。缺少认证信息时不发起请求，仍可手动填写或测试。
- 缓存只属于当前登记／编辑表单，按认证修订、分组、类型、操作系统身份和类型的软件定义区分；切回已检测类型直接复用对应结果和检测时间。操作系统显示名称与当前界面语言不改变系统身份。缓存不会写入浏览器持久存储或数据库，离开表单即清理。
- 缓存最多有效到当前连接凭证到期（10 分钟），地址、端口、用户、认证方式或实际凭据改变时立即清空。新的类型／软件定义不能复用旧定义的检测结果。缓存中的软件观察仍是上次检测事实，不表示持续在线验证。
- 同时触发的检测共用进行中的连接测试，相同选择共用进行中的识别请求。切换到其他类型后，迟到的结果可保留在其自身缓存，但不能覆盖当前选择；认证信息改变或离开表单时中止浏览器请求，迟到结果不能恢复已清空缓存。
- 请求失败不写入缓存。接口成功返回的部分软件未知／检测失败状态仍明确展示，可手动刷新；SSH 失败、主机指纹不符或凭证无效时同时清除连接凭证和缓存。识别纠正了操作系统或回退到其他兼容类型时，按实际返回的系统和类型存放结果。
- 点击「识别系统信息」强制重新检测当前选择；点击「测试连接」重新验证认证信息并清空全部旧识别缓存。复用结果时显示已使用缓存的提示，并保留手动刷新入口。自动检测只读，不打开安装开关或执行安装。

## 接口与执行边界

- `POST /console-api/servers/test-connection`：认证通过后返回指纹、10 分钟有效的加密连接凭证和到期时间。凭证绑定当前连接参数、实际凭据摘要及已有服务器配置修订，不包含原始口令或私钥。
- `POST /console-api/servers/identify-system`：要求当前连接凭证；过期、修改认证信息或替换已保存密钥后均需重新测试。连接还要核对测试成功时的主机指纹。
- 这两个接口继续使用控制台登录鉴权。已有服务器的主机指纹在连接同一地址和端口时仍有效，不能借表单测试绕过。
- 临时 SSH 连接由插件当前生命周期持有，操作结束、失败或插件卸载均关闭。卸载等待已接受工作及迟到连接结束后才释放定义与数据库依赖。
- 保存与软件变更仍沿用 [执行基础](execution-foundation.md) 的持久计划和任务，不因为表单识别增加新的软件变更通道。

SSH 连接从发起到认证成功使用总等待上限，插件配置 `sshReadyTimeoutSeconds` 默认 30 秒，允许 1～300 的整数秒。登记测试、系统识别、后台任务、指标采集和终端采用同一配置，不改变远端命令自身的执行时限。超时按当前阶段返回独立错误码：`ssh_connect_timeout`（尚未建立网络连接）、`ssh_handshake_timeout`（网络已连接，SSH 握手未完成）、`ssh_auth_timeout`（握手已完成，认证仍未完成），提示中的秒数是全过程上限，不是该阶段独享的时限。认证拒绝仍使用 `ssh_auth_failed`；服务器提前关闭连接不能留下未结束的测试请求。诊断不包含口令或私钥。

真实服务器安装和 Windows 软件配方仍不属于本次交付；系统识别和软件检测使用隔离替身验证。SSH 超时修复另使用经授权的测试服务器只读验证认证，不执行远端安装。

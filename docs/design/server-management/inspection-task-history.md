# 巡检报告与任务查询

状态：2026-10-19 已实现。

## 展示规则

控制端仍通过 SSH 主动执行只读巡检，默认约 30 秒检查一次在线服务器。巡检不安装、升级或重启软件，CPU／内存指标继续走独立采集流程。本次不调整断开后的自动重连策略。

- 普通巡检（周期任务和「立即刷新」）不在任务列表展示排队、执行中及逐次成功记录。失败和阻止执行的任务立即显示，保留错误内容。
- 操作系统识别失败、类型定义不可用、必要软件检测未知／健康检查失败、容器查询失败，均记录为巡检异常，不能以「巡检成功」隐藏。Docker 未安装属于容器检查不适用，必要软件尚未安装属于待安装，二者不单独当作检测错误。容器错误不把已连通的 SSH 标记为断开。
- 每台服务器按自然小时汇总；整点后显示刚结束小时的报告，列出成功和异常次数。该小时至少成功一次才生成可见报告；全为异常时只有各条异常任务。含异常的报告标记失败，正常报告标记成功。当前小时暂不显示成功汇总，没有巡检时不伪造报告。
- 小时桶使用 UTC 的整点边界，时间在浏览器按本地时区显示（中国时区同样对应每个整点）。报告时间取小时结束时间；每次检查按完成时间计入小时桶，长任务跨小时只计入完成所在小时。
- 明确的连接测试、必要软件准备及安装任务继续逐条显示，保留运行状态、逐软件结果及实际依赖变更。

## 查询与分页

服务器详情中的任务改为独立查询，不再夹带在每秒刷新的服务器详情中，也不再固定截取最近 20 条。

`GET /console-api/server-jobs?server_id=<uuid>` 返回 `{items,total,page,page_size}`，按记录时间倒序、ID 倒序稳定排序。分页由数据库完成；默认每页 10 条，页面可选 10／20／50／100 条。超出末页时返回实际末页；空结果回到第 1 页。总数与当前页在同一 SQL 快照中读取。

查询条件：`q` 搜索任务 ID、软件标识、原始输出和结构化结果；`action` 筛任务类型；`status` 筛状态；`from/to` 筛时间。起点包含、终点不包含，接口时间必须带时区，页面将本地输入转换为明确的 UTC 时间。关键词按字面匹配，`%`、`_` 不作为通配符。条件在点击「查询」后生效；查询、重置、修改每页数量时回到首页，后台刷新保留当前页和条件。

任务列表每 5 秒刷新，前一次请求结束后才安排下一次；切换查询／服务器或卸载组件时中止旧请求，防止旧结果覆盖新查询。只有普通巡检的逐次成功被收起，不能通过筛选重新显示；可选择「巡检小时报告」查看汇总。

## 存储与验证

新增迁移 `0015_server_inspection_reports.sql` 和表 `server_inspection_reports`，主键为历史服务器身份与小时起点，保存成功数、异常数和最后检查时间。任务完成及汇总计数在同一带租约检查的事务中提交，重复完成、过期执行者不能重复计数。汇总查询不扫描全部原始巡检记录，不依赖浏览器打开或额外定时器；重启后仍可显示已结束小时的报告。

原始 `server_jobs` 保留给任务调度、执行权恢复、操作回执和审计；隐藏列表不等于删除执行历史。服务器删除后仍保留历史身份及汇总。迁移对已有普通巡检回填小时计数，既有成功记录立即从列表隐藏，既有异常保留；旧成功记录未保存的子检查错误无法倒推，不改写其历史结论。

验证包括隔离 PostgreSQL 中的历史回填、成功折叠、当前小时隐藏、错误保留、跨服务器隔离、分页和同时间稳定排序、关键词字面匹配、时间边界、重复完成拒绝，以及容器权限错误仍保持 SSH 在线。测试不会删除真实服务器或其历史。

服务器管理 68 项测试（无跳过）、类型检查与 CES 全量构建通过。本地 9090 页面确认既有 70 次成功巡检合并为一条小时报告，失败记录和软件安装步骤保留，类型／状态／关键词组合查询与重置正常。

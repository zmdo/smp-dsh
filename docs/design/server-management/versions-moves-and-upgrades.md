# C、D 阶段实施记录

日期：2026-10-20。对应 [数据库路线中的 C、D 阶段](data-model.md#9-实施顺序与验收) 与 [已确认的升级要求](group-types-and-i18n.md#12-版本范围自动检测升级与批量安排补充分析)。

## C：版本策略与移组

登记、编辑页面按软件设置版本约束及“自动检测升级”。约束包含继承类型要求、固定完整版本、版本系列、最低版本和包含上下界的区间。大／小版本表示系列；完整固定版本锁定单一版本。服务端以软件定义的版本适配器校验用户范围只能收紧插件要求。有效范围用于检测、候选筛选、依赖预检与执行前复核。

检测偏好默认关闭，独立保存在 `server_software_policies`，不混入安装事实。固定完整版本或达到完整范围上限时显示不能继续检测的原因，保留原偏好；当前软件源暂时没有新版本仍可继续周期检查。只修改检测开关不会改变服务器配置修订，也不会取消已确认的计划；版本约束变化会使旧计划失效。

服务器详情增加“移动分组／更改类型”弹窗。先选择目标分组、目标类型和是否自动安装缺失软件。同一类型在目标组仍有效时保留，否则预选目标默认类型；类型按声明操作系统过滤。版本策略可重新收紧。普通编辑接口拒绝直接修改分组或类型，包含移入空置类型的情况，统一进入预检／确认流程。

预检通过 SSH 重新识别系统、观察实际软件、读取真实包源候选并解析精确包及依赖。满足目标要求的软件保留；关闭自动安装时缺失软件标记 `defer-install`；已安装版本冲突必须形成明确的替换计划。无法识别、系统不符、不支持的替换、依赖冲突等情况阻塞，不猜测实际状态。

确认展示原版本、目标产品版本、原始包版本、包来源、校验值、依赖及服务影响。替换和可能的降级需要确认。关闭弹窗或取消计划不会提交归属。全部步骤成功并验证后，服务器的新分组、类型与策略才在任务完成事务中提交。失败保留原归属，并保存每一步和远端已经发生的变化；远端步骤成功但数据库归属提交失败也会明确记为失败，不丢弃已知远端结果；移入空置类型不会卸载旧软件。

## D：自动检测与升级管理

服务器管理提供独立“升级管理”页面，包含升级建议、升级计划和执行记录三个 Tab。内容面板标题随当前 Tab 分别显示“升级建议”“升级计划”“执行记录”，计划详情归属“升级计划”。壳向页面传入导航回调，供服务器列表／详情跳转使用；返回服务器页面保留原筛选和分页。

2026-10-20 导航调整：侧栏“服务器管理”改为可展开的分组，子入口依次为“服务器实例”“服务器密钥”“升级管理”，不再以模块顶部 Tab 切换这三个页面。进入“升级管理”后，页面最顶部导航栏直接展示“升级建议”“升级计划”“执行记录”三个 Tab，替换顶部的“升级管理”单一标题；内容卡片中不再重复渲染这三个 Tab。侧栏收起时点击服务器管理图标，会展开侧栏并进入当前子页面（首次进入默认为服务器实例）。该布局通过页面注册的 `navigation: 'sidebar'` 声明，顶部导航由页面同名键的 `console.page-navigation` 槽提供，与内容共用插件实例持有的视图状态；平台设置与 Harness 的现有导航保持不变。切换 Tab 重置分页并退出计划详情，查看计划详情会选中“升级计划”；从服务器实例／详情跳转时进入对应范围的“升级建议”。

控制端周期检查开启检测的软件，默认每小时一次，可用插件配置 `updateCheckIntervalSeconds` 调整（60～604800 秒）。控制端停机时暂停，恢复后按每台服务器合并一次待检查任务。服务器不安装定时任务或 Agent。手动检查不打开周期检测开关。

检测仅运行 detect、list-candidates 和 resolve，不执行安装、升级或重启。缺失软件不是升级建议；当前版本超出约束、健康检查失败、源／权限／连接异常有独立结果。真实配置源里的稳定候选经过有效范围、系统架构和依赖解析后才能成为建议。产品版本与精确包身份分别保存，不能以网站最新版本替代实际可安装版本。

每个软件显示当前大版本内、跨大版本两个路径中各自最高的合格目标。完整候选集合用于批量共同版本选择。拒绝只作用于该服务器、软件和精确目标，可撤销；重复检查保留决定，不通过推荐更低目标绕开拒绝。更高目标重新成为建议。推迟按服务器／软件保存提醒时间，到期仅恢复提醒。

建议可按分组、类型、软件、当前／目标版本、连接状态和处理状态筛选，包含已推迟、已拒绝、已安排和检测失败。支持选择本页或全部筛选结果。提交预检时固定 UUID 清单，一次最多 500 台；随后出现的匹配服务器不会加入计划。实例页保留“需要升级”筛选和升级管理跳转。

批量预检要求每个选中软件在全部选中服务器上有共同产品版本。可以为一个计划选择多个软件；不同操作系统／架构各自冻结原始精确包。任何一台没有交集、尚未安装所选软件、已经达到／超过目标或不符合要求，都会阻塞，不能静默排除或降级。依赖对已声明软件的变更不能突破该软件的有效范围。

预检完成后，用户确认具体服务器、版本、软件包、依赖、服务影响、跨大版本、维护窗口、IANA 时区与并发数。默认串行，并发上限 4 台。支持立即开始或预约开始；最晚开始时间限制新任务启动，已开始的任务继续完成验证。客户端按选定时区转换时间，拒绝夏令时不存在或歧义的时间，避免静默选错偏移。

确认摘要绑定目标快照、配置／环境／定义修订、窗口和并发。执行前重新检查实际软件、可用精确包、来源、校验值和依赖，不追随后来发布的最新版。配置、范围、插件定义或实际软件改变时阻塞。插件撤回后不使用缓存定义授权新执行，已经开始的任务及恢复继续按被接受的操作记录核对。

任一子任务失败会暂停尚未开始的目标。队列领取与远端变更开始前均检查父计划状态；已领取但未开始的任务不能绕过暂停。已开始任务有序结束，页面逐台显示结果。暂停、取消不强杀包管理器。恢复、重试和改期使用“重新预检未成功的服务器”，创建新计划并重新确认，成功项不重跑。错过维护窗口的目标记为未开始，计划记为已错过，不在控制端恢复后补升级。

安装、移动和升级共享每台服务器的数据库执行互斥、租约与 fencing token。实际软件变更沿用远端 root 所有的 flock、操作 ID、持久请求及结果日志。失联首先恢复核对，不以新操作 ID 重复执行；无法确定结果时保持恢复状态，不伪造回滚。

## 数据与接口

新增迁移 `0016_server_version_policies.sql`，增加策略、升级建议表和目标预检／开始信息；调整任务约束以支持关联目标的只读预检。它不删除现有服务器、密钥、观察、任务或执行历史。

主要接口位于已鉴权的 `/console-api/server-changes`：

| 路径 | 用途 |
| --- | --- |
| `GET inventory` | 当前服务器与双语类型／软件名称 |
| `POST detect` | 明确指定服务器，只读检测 |
| `GET suggestions` | 建议分页、筛选、固定筛选结果 UUID、检测结果 |
| `POST suggestions/:id/reject/restore/defer` | 拒绝、撤销与提醒时间 |
| `POST versions` | 所选服务器的共同可升级版本及阻塞机器 |
| `POST plans` | 创建升级或移动预检草稿 |
| `GET plans`、`GET plans/:id` | 计划与逐台冻结快照、预检／执行结果 |
| `POST plans/:id/confirm` | 校验预检摘要和修订，确认时间及影响后排队 |
| `POST plans/:id/pause/cancel/retry` | 暂停、取消或为未成功项创建新预检 |
| `GET records` | 每页 20 条执行记录及真实步骤变化 |

检测建议持久化决定与依据；计划独立保存授权；任务与步骤保存执行事实。列表与升级页面共享数据库事实，不能从“检测开关”推导已经升级，也不能从计划成功假设未验证的软件健康。

## 验证与边界

使用隔离 PostgreSQL schema 验证范围、服务端校验流程、预检摘要、移组失败、并发领取、已领取但未开始的暂停、过期窗口、拒绝／推迟持久化、共同版本和偏好独立性。真实 Python 测试以临时目录和包管理器替身运行远端主管与 apt 协议，不操作宿主包管理器。

配方协议的 resolve 请求可以接收 `action: install | upgrade | replace`，配方需要声明支持的变更动作并返回一致动作；旧的初装配方仍可只支持 install。内置 Docker／Compose 配方扩展为 install、upgrade、replace；只使用现有 apt 源，冻结精确包及 SHA256，执行前重解析、下载后验证。显式替换允许已确认的降级，不执行整机 apt upgrade，不添加源或移除冲突包。不受支持的包家族切换／移除阻塞，需插件提供相应可审阅的配方。

Windows 软件变更、自定义操作系统探测、动态新增软件依赖和人工解除未知远端操作仍属于后续扩展，不在 C、D 中以绕过校验方式开放。容器巡检是否按类型能力启用的问题本次未调整；此前读取 Docker 时复用既有 `sudo -n` 权限的修复保留。

本地 CES 已接入新迁移和页面。真实测试服务器的只读检测曾出现 SSH 认证超时，这属于明确的检测错误，不能当成没有更新。本轮不在真实服务器上执行升级或替换。

最终验证：服务器管理 93 项全部通过且无跳过；全仓 228 项中 225 项通过、3 项既有测试跳过、0 失败。TypeScript 严格检查、全仓构建与 `git diff --check` 通过。真实主机只读联调再次遇到 SSH 握手前断连，已在检测结果中保留错误；没有运行真实升级或替换。

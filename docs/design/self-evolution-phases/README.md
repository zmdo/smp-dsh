# 自演进三阶段实施方案

- 状态：方案设计，未实施
- 日期：2026-10-24
- 分支：`ces/self-evolution`
- 评审问题：[自演进三阶段方案问题清单](issues.md)
- 关联方案：
  - [自演进基础设施](../ces-self-evolution-infrastructure/README.md)
  - [内网域名与网络](../ces-self-evolution-infrastructure/INTERNAL_DNS_AND_NETWORKS.md)
  - [OneDev 自动初始化验证](../ces-self-evolution-infrastructure/ONEDEV_BOOTSTRAP_VERIFICATION.md)
  - [三类服务器与首次演进设计](server-types-and-first-evolution.md)

本文把自演进拆成三个阶段，并把验证阶段进一步拆成 P1、P2、P3 三个门禁。每个阶段都必须通过验收后才能进入下一阶段。

所有阶段均按具备外网访问能力设计：允许在线安装 Docker 和系统依赖、拉取镜像与源码依赖，并连接外部模型 API。P3 验证联网条件下的干净环境重建与恢复，不要求离线部署或断网自演进。

## 1. 总览

```text
阶段一：初始开发
  本机 CES + GitHub
  ↓
阶段二：验证测试
  P1：基础服务器 + 测试服务器
  P2：生产服务器 + 全流程
  P3：干净环境重建 + 恢复验证
  ↓
阶段三：正式上线
  生产运行、运维、备份、回滚
```

| 阶段 | 代码托管 | 部署范围 | 触发方 | 测试环境 | 生产环境 |
|---|---|---|---|---|---|
| 阶段一 | GitHub | 本机/测试机 | 本机 | 本机 | 无 |
| P1 | GitHub + OneDev | A + B | 本机 | B | 无 |
| P2 | OneDev | A + B + C | C 上的 CES | B | C |
| P3 | OneDev | 隔离演练 A + B + C | 外部引导，随后由 C 上的 CES 接管 | B | C（生产角色演练） |
| 阶段三 | OneDev | 正式 A/B/C | C 上的 CES | B | C |

## 2. 阶段一：初始开发

### 2.1 目标

在本机完成自演进基础组件开发，代码托管在 GitHub。

```text
开发机器
├─ CES
├─ 自演进插件
├─ 部署脚本
├─ buildspec 模板
└─ 自动化测试
```

### 2.2 代码来源

```text
GitHub
└─ ces/self-evolution
```

### 2.3 需要完成的内容

```text
自演进插件
自演进组
三个服务器类型
Docker / PostgreSQL / OneDev / Caddy recipe
OneDev 项目创建
Agent Token 自动创建
默认 buildspec
发布脚本
回滚脚本
部署文档
```

### 2.4 验收标准

```text
本机构建成功
插件测试通过
OneDev 可在测试服务器启动
CES 项目可创建
Agent 可上线
buildspec 可被 OneDev 解析
简单 Job 可成功执行
```

### 2.5 当前进展

已完成：

```text
自演进插件包
自演进组
基础设施/测试/宿主三个服务器类型
Docker/PostgreSQL/OneDev/Caddy 安装 recipe
OneDev 测试环境
Agent 在线验证
buildspec 解析和执行验证
```

仍需补齐：

```text

```

## 3. 阶段二：验证测试

阶段二必须按照：

```text
P1 → P2 → P3
```

顺序执行，不能跳级。

### 3.1 P1：基础设施与测试环境

#### 目标

把 OneDev 等基础环境部署到基础服务器，但开发、提交和触发仍由本机完成。

```text
本机 CES
  ↓ git push / 触发
A 基础服务器
  ├─ OneDev
  ├─ PostgreSQL
  ├─ Caddy
  ├─ Agent
  └─ 发布执行器

B 测试服务器
  ├─ 候选 CES
  ├─ 测试数据库
  └─ 测试入口
```

C 生产服务器暂不参与正式发布。

#### 本机职责

```text
开发代码
提交到 OneDev
触发 build/test 流水线
查看测试地址
验收候选
```

#### P1 验收标准

```text
本机推送代码
→ OneDev 收到提交
→ build 成功
→ 镜像推送
→ 候选部署到 B
→ 用户可访问测试环境
```

P1 不验证生产替换。

### 3.2 P2：生产服务器与全流程

#### 目标

部署 C 生产服务器，让生产 CES 自己完成开发和触发。

```text
用户
 ↓
C 生产 CES
 ↓ 修改代码
OneDev
 ↓
build/test
 ↓
B 测试
 ↓
用户验收
 ↓
生产发布
 ↓
C 替换自身
```

#### 关键变化

```text
代码提交从“本机”切换到“生产 CES”
流水线触发从“本机”切换到“生产 CES”
生产发布由独立发布 Agent 执行
```

#### P2 验收标准

```text
生产 CES 能修改自己的代码
生产 CES 能提交到 OneDev
生产 CES 能触发流水线
B 能部署候选
用户能验收
C 能按同一镜像 digest 替换自身
失败可回滚
```

P2 不要求清空全部数据。

### 3.3 P3：干净环境重建与恢复验证

#### 目标

在具备外网的隔离 A/B/C 演练环境中，从干净环境部署全部服务，验证按记录的安装步骤、依赖来源和版本能够重新建立自演进系统，再完成一次新代码的开发、构建、测试与发布。另行验证指定备份能恢复业务数据和配置。

#### 网络与外部依赖

```text
允许通过外网安装 Docker、Compose、Buildx 和系统依赖
允许从公共镜像仓库拉取基础设施及构建基础镜像
允许访问 npm 等依赖源及必要的上游源码仓库
允许连接外部模型 API
允许访问外部 DNS，内部服务名按内网 DNS 方案解析
CES 主仓库、候选镜像及流水线由 OneDev 承载
```

外网访问是安装、构建和模型调用的正常前提；外网中断时不承诺这些操作仍可完成。安装包、依赖和镜像的来源与版本必须可追溯，重建不能依赖原服务器未记录的文件或残留缓存。内网隔离用于控制服务器之间的访问，不等于禁止访问外网。

#### 重建与恢复材料

```text
宿主系统前置条件与在线安装脚本
Docker、Compose、Buildx 及系统依赖的版本和下载来源
OneDev、PostgreSQL、Caddy、CoreDNS、CES 和 Agent 的镜像来源及 digest
构建基础镜像、Node/npm/dsh 和测试依赖的版本与获取方式
初始化 compose
OneDev 初始项目、buildspec 和指定 Git 提交的可导入副本
内网 DNS、证书信任和模型 API 配置方式
独立保存的初始化凭据和恢复所需密钥
恢复演练使用的备份及校验信息
```

重建材料、仓库副本和备份应保存在 A/B/C 清理范围之外。模型凭据等敏感配置独立注入，不写入 Git。无需制作完整离线镜像包。

#### 执行流程

```text
外部操作人或引导脚本准备隔离演练 A/B/C
→ 核对清理范围、宿主前置条件和外网访问
→ 按清单清理演练数据与构建缓存，或使用全新主机
→ 在线安装 Docker 和所需依赖，拉取指定版本镜像
→ 配置网络、DNS 和证书信任，启动 A 的基础设施
→ 创建 CES 项目
→ 从外部保留的副本导入指定提交和 buildspec
→ 配置 A 发布 Agent、B 构建 Agent 和执行器
→ 部署 B、C，配置并验证模型连接
→ C 上的 CES 开发新代码、提交并触发流水线
→ B 测试
→ 用户验收指定候选
→ A 将同一镜像 digest 发布到 C
```

全新安装与备份恢复分别验收：全新安装使用初始化仓库和新环境配置；恢复演练从指定备份恢复数据、配置及必要密钥，并检查会话和工作区等业务数据。恢复流程及证据按[基础设施方案](../ces-self-evolution-infrastructure/README.md) §8 补齐。

#### P3 验收标准

```text
联网环境可按记录步骤从干净环境完成部署
Docker、镜像、源码依赖和模型 API 的获取或访问方式明确且验证通过
OneDev 项目、指定提交和 buildspec 可重新初始化
无原环境残留缓存时，仍可构建一次新的代码提交
B 测试通过，用户验收后以同一 digest 发布到 C
指定备份恢复后，业务数据、配置和密钥可用
全流程有记录且可重复
```

#### P3 风险

```text
只清理明确列出的演练资源，不清空真实生产数据
执行入口、重建材料及备份必须处于清理范围之外
清理范围明确列出系统、Docker、持久卷、缓存和仓库的保留或重建方式
外部依赖访问失败时记录实际失败，不能把已有缓存命中当作重建成功
```

P3 必须在隔离的 A/B/C 演练环境执行，通过后再进入正式上线；这里的隔离针对生产数据与资源，不限制所需外网访问。

## 4. 阶段三：正式上线

### 4.1 目标

把 P3 验证过的流程转为正式运行。

### 4.2 内容

```text
DNS 和证书
备份与恢复
监控和告警
发布窗口
回滚预案
审计
密钥轮换
容量规划
值班手册
```

### 4.3 验收标准

```text
生产发布有审批
发布使用不可变 digest
失败可回滚
备份可恢复
OneDev 故障不影响已有生产服务
生产 CES 可自演进
```

## 5. 跨阶段不变量

所有阶段都必须保持：

```text
测试和生产使用同一个镜像 digest
生产发布不重新构建镜像
发布必须经过用户验收
生产部署由独立发布 Agent 执行
测试不能直接访问生产数据库
OneDev 不能持有生产部署私钥
密钥不进入 Git、审计和 AI 上下文
```

## 6. 当前实现缺口

在进入 P1 前必须完成：

```text
1. 安装时自动创建 CES 项目
2. 初始化默认分支和初始提交
3. 自动写入 .onedev-buildspec.yml
4. 自动配置 Job Executor
5. 实现 build/test/release 三个 Job
6. 实现 SSH 部署和健康检查
```

P3 的联网重建清单、引导脚本和备份恢复材料在进入 P3 前准备完成，不作为进入 P1 的前置条件。

## 7. 阶段门禁

```text
阶段一 → P1：
  本机构建、插件测试、OneDev 和 Agent 可运行

P1 → P2：
  本机提交可通过 OneDev 部署到 B，用户可验收

P2 → P3：
  生产 CES 可自行提交、触发、验收并替换 C，失败可回滚

P3 → 阶段三：
  联网干净环境重建、新代码自演进和备份恢复验证通过

阶段三：
  备份、监控、审计、回滚和值班流程可用
```

## 8. 结论

```text
阶段一：把自演进组件做出来
P1：把 OneDev 和测试环境跑通
P2：让生产 CES 自己走完整流程
P3：联网重建，验证部署可复现及备份可恢复
阶段三：正式运行和运维化
```

P1、P2、P3 不能并行跳过。  
尤其是 P3 的重建与恢复，必须在 P2 稳定通过后，在有外网的隔离演练环境完成一次全量验证。

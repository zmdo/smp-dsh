# 工作区组（workspace-groups）

状态：已实现。本文记录会话侧栏如何按工作区组切换。登记一组、绑定目录、声明自己可在哪些组使用，都由插件通过 `workspaceGroups` 扩展。实现前以本文为准，实现后以代码为准。

运行版本钉在 `dsh` `0.2.1-alpha.5`。插件写法以 `.agents/skills/dsh-plugin/` 为准。不修改 `tmp/deepseek-harness`。

## 1. 要解决的事

Harness 会话侧栏把所有工作区平铺在一起，每个工作区下面是它的对话。添加工作区时可以选择任意目录。默认工作区只会在整个安装还是空的时候创建一次，目录在系统「文稿」下的 `deepseek-harness/default-workspace`。

会话侧栏顶部要能切换工作区组，例如「普通工作区组」。切换之后，下面只显示这个组里的工作区，以及这些工作区下的对话。每个组绑定用户主目录下的一个目录，创建对话框先打开在这里；人和插件都可以把工作区建到或选到别处。每个组有自己的默认工作区，也记住这个组上次正在看的工作区。档案里的工作区写成「工作区组/工作区」。

以后的插件，例如运维，用同一套登记再加一组，并声明自己只在哪些组里可用。这一步不实现运维组。插件在进程里只加载一次，不按组加载或卸载。

## 2. 可行性

可行。工作区的创建、打开和会话列表都有现成的宿主接口。分组、绑定目录、关注记录和档案文字可以放在本仓库的插件里。

有两处不能靠配置官方界面完成：

| 限制 | 依据 | 做法 |
| --- | --- | --- |
| 侧栏工作区列表不能过滤 | `sidebar.workspaces` 由现有浏览器整块渲染，快照没有分组参数。再登记这个座位会换掉整棵树 | 不替换这棵树。只把标题「工作区」换成工作区组下拉框，不属于当前组的工作区段落隐藏 |
| 官方目录对话框不能指定起始目录 | 对话框的参数只有打开、忙碌、选中、取消和失败。打开时不带路径，列出的是用户主目录 | 仍用现有的添加工作区。新登记的工作区记入当前组 |

不停用 `ui-workspace`。它在客户端执行 `super(ctx, 'uiWorkspace')`，档案插件的 `inject` 含有 `uiWorkspace`；它也是唯一把 `workspaces` 放进 `slots.provideRoot` 的插件。停用之后，档案和会话正文都等不到这些服务。侧栏树、搜索、拖拽、置顶、改名、分叉和归档都留在原来的浏览器里。本插件不登记 `sidebar.workspaces`，也不盖住 `conversation.hero.workspace`。

`workspaceRegistry.initializeDefault` 不能拿来给每个组做默认工作区。它只在注册表和会话历史都空时成功一次，并且目录固定在文稿目录下。各组的默认工作区由本插件调用 `workspaceRegistry.create` 创建。

绑定目录不是权限边界。宿主接受任意已存在的绝对路径作为工作区，也允许在列目录接口里于别处新建文件夹。本方案不再加一层拒绝。

插件声明可用组也做得到，边界同样明确。进程里的插件不能按组装上或拆掉。判断用这条会话所属工作区的组，不用侧栏当前点中的那一组。没有声明的插件，包括 Harness 自带的命令和文件工具，每个组都能用，因为改不了它们的清单。我们自己的页面可以按声明出现或收起，我们自己的工具可以在执行前拒绝。工具名单在会话创建时已经定下，本插件进不了那个时机，所以模型仍然看得到这个工具，调用时才会被拒绝。

## 3. 结论

| 事项 | 决定 |
| --- | --- |
| 插件 | `@smp/console-workspace-groups`，目录 `plugins/workspace-groups`，补丁 `id` 为 `smp-workspace-groups` |
| 侧栏 | 保留现有工作区浏览器，只把标题「工作区」换成工作区组下拉框。`ui-workspace` 保持启用 |
| 普通组 | 本插件登记。编号 `general`，中文名「普通工作区组」，绑定目录 `~/.smp/workspaces` |
| 扩展 | 宿主插件 `inject` 宿主上的 `workspaceGroups`，登记组、声明可用组、查询归属。浏览器插件 `inject` 客户端上的同名服务，数据来自 `GET /console-api/workspace-groups` |
| 绑定目录 | 相对用户主目录的一段路径。解析后必须仍在主目录里。只决定创建对话框先打开哪里 |
| 归属 | 一个工作区只属于一个组。在当前组里添加的，归入当前组。这一步之前已经存在的，归入普通组 |
| 默认工作区 | 每个组在自己的绑定目录下有 `default-workspace`。界面标题是「默认工作区」 |
| 切换 | 该组有仍属于它的关注工作区时，进入那个。否则进入默认工作区 |
| 档案 | `@smp/console-sessions` 的工作区列和筛选项显示「工作区组/工作区」 |
| 可用组 | 插件用 `allow` 声明自己可用的组。不声明则每个组都可用。按会话所属工作区判断 |
| 这一步不做 | 不实现运维工作区组。不限制工作区可以建在哪里。不搬已有工作区的目录。不重做官方侧栏的树、全文搜索、拖拽排序和水位线。不按组加载或卸载插件。不把工具从模型的工具名单里去掉 |

## 4. 插件登记

宿主和客户端各有一份 `workspaceGroups`，名字相同，不是同一个上下文。宿主 `inject` 为 `['database', 'workspaceRegistry', 'webServer', 'consoleSession']`，用 `provide` 交出宿主服务。客户端 `inject` 为 `['slots', 'workspaces', 'uiWorkspace', 'locale']`，用 `provide` 交出客户端服务。档案和壳的客户端 `inject` 这份客户端服务，不注入宿主服务；宿主上的 `provide` 到不了浏览器。

客户端服务的数据来自 `GET /console-api/workspace-groups`。这条路由先走 `consoleSession.read`，没有会话时返回 401。应答包含已登记的组、每个工作区的归属、各组的关注工作区，以及每条 `allow`。壳用它收起页面，档案用它拼「工作区组/工作区」。

一个组是：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定编号。普通组是 `general` |
| `label` | 侧栏上的名字 |
| `directory` | 主目录下的相对路径，例如 `.smp/workspaces`。不要带 `~` |
| `order` | 切换列表里的顺序。普通组是 0 |

`register` 在插件加载时调用。同一编号登记两次，后一次失败。`directory` 解析时用本进程的用户主目录接上，结果必须等于主目录或位于主目录之下。指向主目录以外、空路径、或解析后不是目录的前缀，登记失败，该插件加载失败。绑定目录不存在时创建它。

运维插件以后自己登记，例如目录 `.smp/ops-workspaces`。本方案不写那个插件。

别的插件不修改本插件里的组清单。要加一组，就 `inject` `workspaceGroups` 并 `register`。要限制自己出现在哪些组，就 `allow`。要知道一个工作区属于哪一组，就查询这个服务。

## 5. 插件在哪些组可用

插件加载时声明：

| 字段 | 含义 |
| --- | --- |
| `id` | 插件自己的稳定编号，例如补丁 `id` |
| `groups` | 可用的工作区组编号。至少一项 |
| `pages` | 这个插件登记的 `console.page` 键。壳用来收起页面。没有页面则省略 |

同一 `id` 声明两次，后一次失败。`groups` 里可以写尚未登记的组编号，先记下，不因此加载失败。检查时该组还没有登记，则这项声明对不上任何工作区。

是否可用只看这条会话所属的工作区落在哪个组。侧栏正在显示另一组时，不改变已经打开的会话。

| 声明 | 结果 |
| --- | --- |
| 没有 `allow` | 每个组都可用。Harness 自带插件属于这一类 |
| 工作区的组在 `groups` 里 | 页面出现，工具可以执行 |
| 工作区的组不在 `groups` 里，或该组还没登记 | 列出的页面从壳里收起。工具执行时拒绝，说明当前工作区组不可用 |

模型的工具名单不改。拒绝发生在执行时，不发生在登记工具时。

没有打开的会话时，页面按侧栏当前组里即将进入的那个工作区判断，也就是关注工作区，没有关注记录时用默认工作区。会话一打开，改回按该会话所属的工作区判断。

## 6. 侧栏

侧栏仍是现有的工作区浏览器，本插件不另画一棵树。标题「工作区」换成下拉框，列出已登记的工作区组。当前组以外的工作区段落不显示。搜索、添加、置顶、改名、分叉和归档都还是原来的控件。

添加工作区仍走原来的对话框。确认后把新工作区记入当前组。路径已经属于别的组时，保持原组。

## 7. 默认工作区与关注

组登记完成、绑定目录可用之后，若该组还没有默认工作区，就在 `{绑定目录}/default-workspace` 创建目录并登记工作区，归入这个组。目录已经是一个工作区时，把那个工作区归入这个组，当作它的默认工作区，不另建第二个。

人打开本组某个工作区里的会话时，把该工作区记为这个组的关注工作区。切换到这个组时：

| 情况 | 进入 |
| --- | --- |
| 关注的工作区还在，并且仍属于这个组 | 那个工作区 |
| 否则 | 这个组的默认工作区 |

进入是打开该工作区里已有的空白会话；没有空白会话时新建一条。不自动发送消息。

已经存在、还没有分组记录的工作区，在第一次启动时归入 `general`。不移动它们的目录。原来位于文稿目录的默认工作区也按这条归入普通组，不把它改成普通组的默认工作区。

## 8. 档案

档案列表和筛选里，工作区显示为「工作区组/工作区」。组名来自 `workspaceGroups`，工作区名沿用现在的标题；存储标题仍是默认目录名时，工作区名显示「默认工作区」。没有分组记录时，组名用「普通工作区组」。筛选比较的仍是工作区路径，选项文字改成上面的组合。

## 9. 表

迁移放在 `plugins/database/migrations/`，文件名接在当前最后一张迁移之后。

```sql
create table if not exists workspace_group_members (
  workspace_id text primary key,
  group_id text not null,
  is_default boolean not null default false
);

create table if not exists workspace_group_focus (
  group_id text primary key,
  workspace_id text not null
);
```

组的名字和绑定目录不入库，由登记它的插件在每次启动时提供。成员和关注记录留在库里。

## 10. 测试

用 `node:test`。不打开浏览器，不连真实的目录对话框。

- 相对路径 `.smp/workspaces` 落在用户主目录下。主目录以外的路径登记失败。
- 新添加的工作区记入当前组。已有工作区只在没有成员行时归入 `general`。
- 一个工作区已属于别的组时，再次添加不改归属。
- 组没有默认工作区时，默认路径是 `{绑定目录}/default-workspace`。该路径已是工作区时，把它标成默认，不创建第二个。
- 有关注记录时切换进入那个工作区。关注的工作区已不属于这个组时，进入默认工作区。
- 档案标签是「普通工作区组/默认工作区」。没有成员行时也用普通组的名字。
- 没有 `allow` 的插件，在普通组和另一个已登记组里都可用。
- `allow` 只写了另一个组时，普通组里的工作区使它的页面收起，工具执行被拒绝。工具仍在名单里。
- `allow` 写了还没有登记的组时，登记本身成功，对上现有工作区时不可用。
- 会话所属的组与侧栏正在显示的组不同时，按会话所属的组判断。

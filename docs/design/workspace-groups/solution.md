# 工作区组问题的做法

状态：待实现。本文处理 `issues.md` 里的 6 个问题。不修改 `tmp/deepseek-harness`，不停用 `ui-workspace`，不另画侧栏树。和 `design.md` 第 6、7 节不一致的地方，以本文为准。

现有库里的成员、关注、会话和工作区都是测试数据。新迁移不抄旧行。测试开始前清空这些记录，避免旧的未分组会话混进新结构。

## 1. 搜索框不再因切换而展开

`.smp-chat-side` 由壳在根范围创建一次，并一直持有这个节点。会话页头里只留「会话 / 档案」。页头槽是 `session-maybe`，会话一换就会把现在放在页头里的侧栏拆掉。工作区浏览器挂在这个侧栏上，重新挂载时只要 `searchRequest` 不是 0，搜索框就会再展开。

侧栏改挂到页面根上，仍用现在的绝对定位（`left: 0; top: 49px`），不放进会形成新定位包含块的轨道里。切换组仍会换会话，侧栏节点不再重建，搜索框保持关闭。

## 2. 切换组时打开上次的会话

每个组记下正在看的工作区和会话。每个「工作区 × 组」记下该组最后一次打开的会话。已归档的会话不记、也不恢复。

切到一个组时：

| 情况 | 打开 |
| --- | --- |
| 记下的会话还在，且它的工作区仍属于这个组 | `uiWorkspace.openSession` |
| 这条会话已经没了，关注的工作区还在 | 该工作区在这个组里记下的会话；没有的话，打开其中最近更新的一条非空白会话 |
| 上面都没有 | 该组的默认工作区。这时才调用 `openWorkspace`，新建或复用空白会话 |

组切换走上面这张表，不直接调用 `openWorkspace`。

会话芯片里的工作区项由官方 `onPick` 接到 `openWorkspace`，插件换不了这个回调。点中一项时，在捕获阶段拦住点击：工作区已属于当前判断组时，改为 `openSession` 打开第 2 条表里的会话，并阻止官方 `onPick`。这样不会先造出一条空白会话。

## 3. 不同组可以叫同一个名字

显示名写在成员行的 `display_label` 上，按「工作区 × 组」各存一份。侧栏行、档案列、会话芯片上的文字都用这个名字。没有显示名、且 Harness 标题是 `default-workspace` 时，显示「默认工作区」。

新建工作区后，把 Harness 给出的标题写入该组的 `display_label`，再把 Harness 标题改成 `wg:` 加工作区编号。`default-workspace` 保持不动，好让官方的「默认工作区」映射继续生效。人把默认工作区改成别的名字时，再按下面的重命名处理。

官方重命名比较的是全部工作区的存储标题，对话框初值也来自存储标题，不读我们盖在行上的文字。存储标题保持为 `wg:` 加编号之后，别的组的显示名不会撞上这次检查。对话框一打开，若存储标题是这个内部值，就把输入框设成该组的显示名。输入框是受控组件，只改 DOM 的 `value` 不会改确认时提交的草稿，需要写入原生 value 再派发 `input`，让 React 的 `onChange` 更新草稿。

同一个组里不能有两个相同的显示名。官方冲突提示比较的是存储标题，对不上显示名。确认按钮按下时，若本组已有这个显示名，拦住这次点击，在对话框里写「已存在名为“…”的工作区。」，不调用官方重命名。通过之后，把新名字写入当前组的 `display_label`，并把存储标题设回 `wg:` 加编号。另一组可以保留自己的显示名。

## 4. 同一个目录可以属于多个组

Harness 仍是一个目录一条工作区。同一路径再创建，返回原来的那条。成员改成多对多，主键是 `(workspace_id, group_id)`。

在组 B 里打开一个已经属于组 A 的目录时，给 B 加上一行，A 的行留着。两侧栏都能看到它，会话仍挂在这一条工作区上。不再返回「这个目录已经属于…」。新行的显示名复制 A 的显示名；之后在某一组里改名，只改那一行。

每组仍只有一个默认工作区，默认标记按组清除。

工作区从 Harness 列表消失时，成员行留着，目录留着，供第 6 条把未分组会话对回去。这一行的默认标记清掉，关注记录若还指着它，改指该组现在的默认工作区。

一条会话属于哪个组：工作区只有一个组时，就是那个组。有多个组时，用打开这条会话时写入的组。这个对应单独放在 `workspace_group_session`。打开会话时，若当时的判断组仍包含该工作区，就写成这个组。判断页面和工具时读这张表；行还在、但该组已经不再包含这个工作区时，改用剩下的那一个组。

## 5. 会话里的工作区菜单只列出当前组

判断组沿用第 4 条：有打开的会话时用 `workspace_group_session`，没有会话时用侧栏选中的组。

菜单里的工作区项与工作区快照顺序一致，后面才是「添加工作区…」。菜单按钮上没有工作区编号。按快照顺序把不属于判断组的工作区项隐藏，并把按钮设为 `disabled`。菜单的键盘行走是 `button:not(:disabled)`，只隐藏的话方向键仍会落到别的组。添加一项留着，不参与这个顺序。

创建：

- 目录对话框仍从用户主目录打开。官方对话框不接收起始目录。
- 从侧栏的添加按钮确认时，成员记入侧栏选中的组。从会话芯片的添加确认时，成员记入当前判断组。两条路径都用官方目录流，确认后的新工作区若还没有任何成员行，按当时打开对话框的那一侧归组。
- 选中的路径已经是工作区时，按第 4 条给这个组加上成员，再按第 2 条打开记下的会话。

## 6. 「未分组」按组拆开

官方仍只画一栏「未分组」。本组按会话把行隐藏：对不上当前组的会话隐藏；这个组一条都不剩时，整栏隐藏。

一条未分组会话属于哪些组，按顺序只取第一条命中的：

| 顺序 | 条件 | 组 |
| --- | --- | --- |
| 1 | `cwd` 等于某个现存工作区的目录 | 该工作区所属的那些组 |
| 2 | `cwd` 等于某成员行记下的目录 | 该行的组。工作区已经从列表消失时，靠这一格 |
| 3 | `cwd` 落在恰好一个组的绑定目录里 | 那个组 |
| 4 | 以上都不是 | 只在普通工作区组 |

`directory` 在写入成员时记下，不随工作区删除而抹掉。

## 7. 表

新迁移接在 `0010_workspace_groups.sql` 之后。删掉旧表，按新结构创建，不插入旧行。

```sql
drop table if exists workspace_group_session;
drop table if exists workspace_group_focus;
drop table if exists workspace_group_members;

create table workspace_group_members (
  workspace_id text not null,
  group_id text not null,
  is_default boolean not null default false,
  display_label text,
  directory text,
  last_session_id text,
  primary key (workspace_id, group_id)
);

create table workspace_group_focus (
  group_id text primary key,
  workspace_id text not null,
  session_id text
);

create table workspace_group_session (
  session_id text primary key,
  group_id text not null
);
```

## 8. 测试

用 `node:test`，不打开浏览器。

- 记下的会话还在时，切换组得到这条会话。已归档的会话不恢复。
- 会话没了时，落到该工作区在这个组里最近的一条非空白会话；工作区也没了时，落到默认工作区。
- 两个组的显示名可以相同。同一个组里的第二个同名在确认前被拒绝，Harness 标题不变。
- 一个目录已属于 A 时，再在 B 里打开，两行都在。在 B 里改名不改变 A 的显示名。
- 工作区同时属于 A 和 B 时，从 B 打开的会话，页面判断用 B。
- 会话在 A 组时，菜单里留下的工作区编号只有 A 的成员。被隐藏的项同时是 `disabled`。
- 未分组会话的目录等于某成员行时，只算那个组。对不上时只算普通组。该组没有未分组会话时，这一栏不显示。

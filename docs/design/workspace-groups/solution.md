# 工作区组修复方案

状态：实现中，尚未完成全部验收。本文按 2026-10-19 确认的需求重新编写，替代原有 solution.md；界面边界按用户最新要求收紧为保留官方侧栏，只增加工作区组切换。本文记录目标行为和实现方案，不表示修复已经完成。

适用版本：dsh `0.2.1-alpha.5`。插件开发遵守 `.agents/skills/dsh-plugin/`。本文与 `design.md` 冲突时，以本文为准；`issues.md` 作为历史问题记录，其中的原因判断仍须用源码和测试核对。

## 1. 已确认的规则

| 事项 | 规则 |
| --- | --- |
| 目录归属 | 一个真实目录只能属于一个工作区组。通过不同路径或软链接访问同一真实目录，也视为同一目录 |
| 同组再次添加 | 复用已有工作区，打开该工作区的有效会话，不重复登记 |
| 跨组再次添加 | 拒绝，说明所属组和工作区，提供前往对应工作区的链接；点击链接后才导航 |
| 工作区名称 | 不同组允许同名，同组禁止重名 |
| 切换组 | 恢复该组上次打开的有效会话；没有可恢复会话时按第 6 节回退 |
| 打开会话 | 侧栏跟随该会话所属组，包括从档案、搜索和外部入口打开的会话 |
| 会话归属 | 属于现存工作区的会话跟随该工作区所属组；不属于任何现存工作区的会话统一进入系统组“未归属”。查看会话不改变其归属 |
| 移除工作区 | 删除工作区登记，保留目录和会话；失去工作区关联的会话统一进入“未归属”，普通组不再创建“未分组”栏 |
| 未归属组 | 稳定编号 `unassigned`，系统内置且不可删除，不绑定目录、不拥有工作区、不创建默认工作区，禁止添加或创建工作区 |
| 界面接入 | 保留 dsh 官方侧栏 UI、组件、行操作、选择器与对话框，只在原侧栏增加工作区组切换；通过数据和动作适配实现分组规则，不自行重画侧栏 |
| 宿主 | 不修改 dsh 源码，保持 `ui-workspace` 启用，继续使用现有工作区、会话和导航服务 |
| 测试数据 | 现有会话与工作区记录均为可删除的测试数据。正式测试前清空相关历史，不迁移旧记录，不为兼容旧数据限制新结构 |

普通组仍由插件通过 `register` 扩展；`unassigned` 是保留编号，业务插件不能重复登记或覆盖。本轮不实现运维组、普通组之间迁移目录或会话、按组加载或卸载插件。普通组的绑定目录继续作为默认目录和目录浏览的起点，允许选择绑定目录以外的位置。

移除工作区后保留目录的历史归属。同目录重新添加时仍归原组，跨组添加仍拒绝；归属释放或迁组需要以后单独设计。目录原组用于重新添加时的冲突检查，不用于把失去工作区关联的会话留在原组，“未归属”也不因此拥有该目录。

“未归属”直接显示会话列表，允许查看、搜索、改名、分叉、归档和删除已有会话，不提供添加工作区或脱离工作区的新建会话入口。切入时恢复上次有效会话，没有则打开最近更新的非空白、未归档主会话，仍没有就显示空态；不得为填充这个组创建默认工作区或空白会话。

## 2. 当前问题与修复范围

当前客户端通过 DOM 隐藏官方侧栏的工作区段落，没有改变官方组件使用的全局数据。修复必须覆盖数据选择、导航和宿主操作，不能只补显示效果。

| 问题 | 修复 |
| --- | --- |
| 切组后搜索框自行展开 | 侧栏挂载点保持稳定；搜索请求只消费新请求，不在重新挂载时重放历史计数 |
| 切组只进入空白会话 | 保存组和工作区的会话关注记录，恢复时优先打开具体会话 |
| 跨组重命名冲突 | 本项目宿主服务按组校验，通过 dsh 的工作区实体方法持久化标题 |
| 选择其他组的已有目录没有明确结果 | 添加入口统一调用带组参数的宿主接口，返回可导航的结构化冲突 |
| 会话工作区菜单跨组、创建归错组 | 选择器只投影当前组；创建请求固定携带交互开始时的目标组 |
| “未分组”在每组重复 | 撤掉普通组里的“未分组”栏，所有没有现存工作区关联的会话统一显示在“未归属”系统组 |
| 搜索、平铺模式绕过分组 | 分组、目录树、平铺和侧栏搜索共用会话归属与筛选逻辑 |

## 3. 插件职责与界面接入

### 3.1 宿主服务

`@smp/console-workspace-groups` 负责目录归属、成员、会话组解析、关注记录和工作区操作。保留 `register`、`allow`、可用性查询，补充以下能力：

- 按真实路径解析目录所属组，按工作区或会话查询所属组。
- 在指定组内添加或复用工作区、重命名、移除工作区登记。
- 返回恢复导航所需的组、成员、会话组投影和关注快照，明确区分普通组与系统组。
- 对数据库与 dsh 工作区登记之间的中断进行恢复。

所有本项目的工作区添加、重命名和移除入口都调用这份服务；后续业务插件也复用它。dsh 原有 RPC 的参数中没有工作区组，不能假设它会自动执行这些规则。

### 3.2 客户端服务

客户端 `workspaceGroups` 维护宿主快照、当前组和进行中的导航，向壳、档案与工作区组件提供统一的查询和动作。组件通过订阅读取状态，通过服务发起操作。

组类型用普通组与系统组的判别联合表达；“未归属”的类型不包含绑定目录、默认工作区和可添加工作区等普通组能力，不能填空目录字符串来绕过普通组登记校验。

组和目录规则不依赖浏览器传来的显示名、隐藏状态或调用先后顺序。宿主负责归属与重名校验；客户端负责交互状态和呈现。

### 3.3 界面与生命周期

- `frame` 在根作用域持有稳定的会话侧栏节点，页头只负责“会话 / 档案”等页头内容。主会话切换不能销毁侧栏节点或把新会话编号作为侧栏 React key。
- 组切换沿用原来侧栏标题位置的选择控件；工作区列表、搜索、视图选项、添加按钮、行菜单和对话框继续使用官方组件与样式，不建立本项目自己的侧栏列表。
- 壳继续渲染官方 `sidebar.workspaces`，不增加用于替代它的 `console.workspaces` 槽。由壳的渲染边界适配当前组的数据与业务动作，官方登记项继续持有其原有子槽。
- 固定版本的渲染器按标准 props、登记项注入、owner props 的顺序合并 props；利用现有 owner props 渲染边界传入分组后的 `useWorkspaces`、`useSessions` 与组内动作。此适配依赖已核对的固定版本，升级 dsh 时需重新核对并回归；不改写官方登记项、全局服务方法或 dsh 源码。
- 保持官方 `ui-workspace` 的服务与根数据供给，不覆盖全局 `workspaces` 快照，不影响会话正文和档案的依赖。
- 官方行操作及工作区操作对话框原样保留；搜索、置顶、会话改名、分叉、归档、运行提示、拖拽排序和键盘操作都属于回归范围。分组数据先在完整权威快照中解析归属，再投影给原组件，不能让过滤后丢失的工作区把其他组会话变成“未分组”。
- 不再注册侧栏或工作区选择器的自绘替代项，也不重复声明官方子槽。会话工作区选择器由适配登记复用 `conversation.hero.workspace` 原登记中的官方组件，提供按当前会话所属组筛选的工作区 hook，并接入组内导航与添加动作；鼠标和键盘都使用组件收到的同一份列表。
- 选择器的目录浏览继续复用官方已安装的目录流组件及其注入，通过本插件持有的独立子槽别名渲染。官方 `conversation.hero.workspace.directoryFlow` 仍由原登记持有，不重复声明；原目录流更换或卸载时同步更新别名并清理订阅。上述组件复用依赖固定版本的公开槽登记面，升级时需回归。
- 快捷键也属于接入范围：官方 `session.search`、`workspace.add` 等命令已登记，注册表会拒绝重复编号和默认按键。先核对并通过槽的公开登记、注入面适配已有请求源和动作，不能再登记同名命令或假设存在覆盖 API。

移除当前 `paint`、全页 `MutationObserver` 和隐藏工作区段落的逻辑。组切换控件保留原位置所需的最小样式；不修改官方行和菜单样式，不通过按钮顺序推测工作区编号，不拦截官方确认按钮，不派发合成 input 事件改写官方 React 草稿。

## 4. 新数据结构与测试前重置

用户已明确允许删除现有测试会话，并要求测试前清空相关历史。新结构按目标行为设计，不编写旧成员、旧关注、旧标题和旧会话的迁移或兼容分支。开发过程中可以重建工作区组表；结构变更通过新的编号 SQL 交给现有数据库版本管理器执行，不修改已经应用的 `0010_workspace_groups.sql`。

### 4.1 新结构

一个工作区只对应一个组，成员以 `workspace_id` 为主键。计划的数据结构如下，字段可在实现中按约束进一步精简，不以保留旧表形态为前提。

| 表 | 字段与用途 |
| --- | --- |
| `workspace_group_members` | `workspace_id` 为主键，保存 `group_id`、非空规范目录 `directory`、`is_default` 和可空的 `last_session_id`。没有“旧记录目录未知”的特殊状态 |
| `workspace_group_focus` | `group_id` 为主键，保存可空的 `workspace_id`、`session_id`。“未归属”的工作区编号固定为空，只记最后查看的会话 |
| `workspace_group_directories` | 以规范目录 `directory` 为主键，保存唯一 `group_id` 与操作状态。状态至少区分创建未完成和归属已确认，供重启恢复使用；移除工作区登记不删除已确认归属 |

会话当前组由权威工作区会话账户实时派生，不再增加独立的会话到组持久表。工作区删除、重新登记或会话关联变化后重新计算，避免成员与会话组两份状态不一致。历史来源如需展示，只作为附加信息，不参与归属与插件可用性判断。

从空数据创建必要的非空、唯一和每个普通组至多一个默认成员约束；成员和目录归属不能指向 `unassigned`。默认标记只针对仍存在的工作区有效，启动和工作区变化后仍需检查实际登记是否存在。这些运行期一致性检查不属于旧数据兼容。

组定义仍由插件提供，不把组名和绑定目录复制为数据库中的权威定义。已有归属对应的插件暂未登记时保留组编号；显示组不可用，不把它的工作区或会话改归其他组。

### 4.2 正式测试前的清理范围

实现可重复执行的测试重置流程。首次集成和浏览器验收前，清空当前项目测试环境中的以下历史，而不只是清空工作区组表：

- `console_session_event`、`console_session` 中的全部会话事件、元数据、分叉及子代理会话记录。
- 所有工作区组成员、目录归属、会话归属、关注记录和未完成操作状态，包括此前测试版本遗留的相关表。
- `console_storage_record`、`console_storage_global` 中 `unit_name = 'workspace'` 的工作区登记及全局状态，包括置顶、归档、排序和默认工作区标记。其他存储单元不清空。
- 当前测试站点中关联会话和工作区的浏览器持久状态，包括当前会话、草稿与附件引用、分组选择、展开和排序状态。保留登录、主题和其他无关配置。
- 本次测试使用的旧导入源和会话历史恢复源：核对实际启用的持久化后端，只处理当前项目测试配置范围内会被再次读取的历史文件或缓存。

工作区存储插件会在数据库没有单元元信息时尝试导入 `importRoot/workspace.json`。重置时必须清空或隔离这份测试导入源，或者保留有效的空单元元信息以阻止旧文件再次导入；不能清完数据库又把旧工作区读回来。当前会话 JSONL 后端已停用，仍应核对测试配置没有启用其他历史恢复源。

清理只删除应用历史记录及明确识别的测试恢复源，不删除工作区指向的真实项目目录、项目文件、账号、模型配置、密钥、无关存储单元或数据库版本管理记录。

### 4.3 清理与测试顺序

1. 确定当前项目使用的测试数据库、dsh 配置目录和浏览器站点，记录清理范围与清理前数量。
2. 停止当前测试实例和相关后台任务，等待会话写入与存储队列结束，避免内存状态在清理后写回数据库。
3. 在数据库事务中按依赖关系清空历史，执行本轮所需的新结构初始化；处理测试导入源并清除对应浏览器历史状态。
4. 启动前验证相关表和工作区记录为空。启动后只允许出现普通组初始化生成的默认工作区，以及本次测试显式创建的记录；“未归属”不能生成工作区。
5. 用本轮新建的组、目录和会话运行测试。独立测试场景之间重置或使用隔离数据；同一重启持久化用例中不能在重启时清空待验证记录。
6. 交付时报告实际清理的记录范围、清理结果和测试结果。未经执行不能声称历史已清空。

重置是测试准备动作，不得挂到普通启动、插件热重载或每次组登记上。此处的清空授权不改变产品正常运行时“移除工作区保留会话”的规则。

## 5. 添加工作区与跨组冲突

提供 `POST /console-api/workspace-groups/workspaces`，请求包含 `groupId`、目录 `path`，以及需要用户确认名称时提交的 `title`。原来的“先创建，客户端扫描后 claim”不再作为本项目添加流程。

宿主处理顺序：

1. 验证登录、目标组和目录。目标为 `unassigned` 时直接拒绝，所有创建与认领接口都检查这一约束；目录必须存在且是绝对路径，使用与 dsh 一致的 `realpath` 规范化规则。
2. 查询持久目录归属和现有工作区成员。创建未完成时先协调该操作；本项目之外新增的未归属工作区按明确的普通组接纳规则处理，不读取侧栏状态猜测归属。
3. 目录属于其他组时返回 409，不创建工作区、不创建或打开会话、不改成员或关注。
4. 目录已属于本组且工作区仍存在时直接返回它；同目录同组再次添加不触发重命名。
5. 目录未归属或本组工作区已移除时，按组校验拟用标题，原子预留目录归属，调用 `workspaceRegistry.create`，完成成员与默认标记写入。同目录重新登记后，核对同 cwd 的未归属会话，通过公开的 `attachSession` 能力恢复可验证的关联；不能仅改客户端显示的组编号。
6. 客户端拿到成功结果并刷新归属快照后，才执行第 6 节的工作区导航。

冲突使用可判别的结果，例如：

```json
{
  "code": "workspace-group/directory-conflict",
  "detail": "该目录已属于「默认组」的「项目 A」。",
  "owner": {
    "groupId": "general",
    "groupLabel": "默认组",
    "workspaceId": "workspace-id",
    "workspaceTitle": "项目 A"
  }
}
```

客户端把 owner 数据渲染成“前往该工作区”的导航链接，不解析错误文案，也不渲染服务端 HTML。链接使用本项目的组导航动作，不虚构 dsh 未提供的深链协议。原工作区已移除时，冲突结果的 `workspaceId` 可空，链接改为“前往所属组”；在该组重新添加目录可以恢复工作区登记。

添加对话框记录打开时的目标组。确认期间不能因侧栏或会话变化而更换请求组；提交前可取消且不产生工作区和会话，提交中禁用重复确认和取消，成功后按该目标导航。网络断开后查询实际结果再重试，不能把客户端中止请求等同于宿主没有完成创建。

所有添加、改名和默认工作区创建经宿主服务协调，序列化同组名称竞争和同目录竞争；目录主键作为归属唯一性的持久约束。数据库与 dsh 登记使用不同存储，不能宣称一次 SQL 事务涵盖两者。创建中断后，启动恢复按预留状态和真实注册表补全；确认创建失败且没有生成登记时，撤回本次新增的预留，保留已有归属。

目录浏览优先复用现有目录服务。沿用官方目录对话框时明确从用户主目录起步；需要以组绑定目录为起点时，由插件自有浏览组件调用 `listDirectory(path)`、`createDirectory`，不向官方对话框传不存在的起始目录参数。

## 6. 组与工作区导航

区分“继续上次会话”和“新建会话”。前者优先调用 `uiWorkspace.openSession`；后者才使用创建或复用空白会话的能力。

切换普通组时按顺序选择：

| 顺序 | 目标 |
| --- | --- |
| 1 | 该组保存的会话仍存在、未归档、可作为主会话打开且仍属于本组的现存工作区，直接恢复；失去工作区关联后不再从原组恢复 |
| 2 | 关注工作区仍存在且属于本组，先恢复它保存的有效会话，否则打开其中最近更新的非空白、未归档主会话 |
| 3 | 无法恢复以上目标时，确保本组默认工作区存在，打开或复用该默认工作区的空白会话 |

切换“未归属”时，先恢复它保存的有效未归属会话，再尝试最近更新的非空白、未归档未归属主会话，最后显示空态。不得执行普通组的默认工作区回退。打开未归属会话时侧栏同样自动切到“未归属”。

工作区选择器选中某一工作区时，仅在该工作区内执行相同的恢复规则；没有可恢复会话时，在所选工作区打开或复用空白会话，不跳到其他工作区。

选择器先通过自己的关闭回调收起菜单，再交给统一导航动作，不能调用会隐式进入空白会话的官方 `onPick` 后又恢复历史会话。已有会话的草稿和附件保留在各自会话，不因恢复另一条会话而搬移或覆盖；显式新建会话的草稿初始化继续使用 dsh 的对应能力。

空白会话若确实是上次打开且仍有效，可以恢复。已归档、已删除和子代理会话不作为自动恢复目标；候选会话必须同时通过归属检查，不能只比较 cwd。

打开并确认主会话选中后才保存关注：普通组记录工作区和会话，工作区记录最后会话；“未归属”只记录会话。一个工作区内更换会话也必须保存，不能继续只按“组编号 + 工作区编号”去重。

客户端使用统一导航协调器：

- 显式切组或点冲突链接时，记录目标组和本次导航编号，解析目标并发起导航。
- 导航尚未完成时，当前旧会话的订阅事件不能把侧栏切回旧组；旧界面待切换期间的功能判断仍按实际会话归属。
- 目标会话真正选中后，确认所属组、同步侧栏、持久化关注。失败时保留原会话并还原侧栏，显示失败原因。
- 从档案、搜索、刷新恢复和其他入口打开会话时，同样观察主会话变化并切到它所属组，不要求所有调用方都经过某个按钮。
- 连续快速切组时，较早的异步结果不能覆盖最新选择或写错关注。请求取消及序号检查必须覆盖目标解析、快照加载和关注保存。

会话组解析和候选会话数据未就绪时，等待或显示加载状态，不能把临时缺失误当普通组或“未归属”并保存关注。

## 7. 工作区名称

继续用 dsh 工作区实体的真实 `title` 存储名称，不新增按组覆盖的显示名，不把标题改成 `wg:` 等内部编号。

### 7.1 当前限制所在层次

当前工作区重命名由官方 `WorkspaceBrowser` 提供对话框，先对完整工作区快照检查重名，再调用 `workspaces.rename`；宿主的 `WorkspaceCommands.rename` 又对完整注册表检查一次。因此只改插件后端仍会被官方前端阻止，只改前端也仍会被官方 RPC 阻止。

底层工作区实体没有全局唯一标题约束。固定版本的公开 `Workspace` 类型明确允许重复标题，公开 `setTitle(title)` 用于持久化标题，官方 rename 命令校验后调用的也是这个方法。

### 7.2 接管的入口与调用链

保留官方工作区行的“重命名”入口与对话框。对话框读取本组工作区投影，前置重名校验自然限定为组内；通过侧栏渲染边界传入本项目的 `renameWorkspace` 动作，替代该组件原来调用的全局改名 RPC。会话重命名仍使用官方能力。

调用链固定为：官方工作区改名对话框 → 适配后的 `renameWorkspace` → `POST /console-api/workspace-groups/rename`，请求 `{ workspaceId, title }` → 本项目宿主服务组内校验 → `workspaceRegistry.get(workspaceId).setTitle(title)`。

不调用官方 `workspaces.rename`，不替换或 monkey-patch 它的实现，不修改官方 RPC 路由，不直接写工作区存储表。官方服务继续启用，标题更新仍由 dsh 实体完成持久化，并通过现有工作区快照传播给会话芯片与档案。

宿主处理规则：

1. 宿主查询工作区的固定所属组。
2. 对输入去除首尾空白，拒绝空名称；按当前明确的大小写敏感规则检查本组其他现存工作区。默认工作区的本地化显示名也应避免产生同组重名行。
3. 通过后调用 `workspaceRegistry.get(workspaceId).setTitle(title)` 持久化。这个公开方法存在于当前固定版本；dsh 全局重名限制在 `WorkspaceCommands.rename`，因此本项目的组内改名不走该命令。
4. 输入框 Enter 与确认按钮提交同一个动作，校验失败时保留草稿并显示原因。

组编号由宿主根据工作区成员查出，不采信客户端为了避开冲突传入的组。检查和保存与工作区创建、其他改名请求共用组内操作队列，避免两个请求同时通过同名检查。不存在的工作区返回稳定的目标消失错误。

创建工作区时也执行同组名称校验。目录名作为初始名称，若同组已存在同名的不同目录，要求用户修改名称后再完成创建；跨组同名直接允许。同目录同组的复用不受此步骤影响。

侧栏、选择器、会话芯片与档案都读取持久标题，默认标题仍按现有规则本地化为“默认工作区”。标题更新失败不改界面中的已保存名称。

### 7.3 生效边界

这项修复以向原组件提供组内数据和改名动作为前提。若仍向原对话框提供全局工作区列表，或动作仍调用官方 `workspaces.rename`，全局冲突限制依然存在，不能把该路径算作已修复。本项目全部工作区改名入口和后续业务插件必须调用上述组内改名服务，浏览器验收检查实际请求路径。

## 8. 列表、搜索与插件可用范围

侧栏保留官方搜索收放行为和布局；组切换控件沿用原有覆盖标题位置的实现，搜索展开期间随原标题收起，不新增独立搜索栏或重排官方工具栏。切组和会话切换不会自行产生搜索请求。接入官方计数请求源时，仅处理本次订阅后新增的请求，不能把挂载时已有非零计数当成新请求。

所有侧栏模式先解析会话所属组，再生成列表：

- 工作区分组、目录树和平铺都只包含本组工作区与本组会话；有嵌套目录时也不能把其他组的工作区带入树中。
- “未归属”从完整工作区快照选出不在任何当前工作区会话账户里的主会话，直接显示会话列表；普通组中不画“未分组”栏。不能先删掉其他组工作区，再把那些工作区的会话误判为未归属。
- 侧栏搜索限当前组，标题搜索和消息搜索采用相同范围。正文搜索若宿主只支持全局有上限结果，需要新增本项目的按组查询能力，先约束候选会话再截断；不能对已截断的全局结果事后过滤并当作完整结果。
- 档案保留跨组检索能力，支持按组和工作区筛选。普通会话的工作区标签为“组名/工作区名”，未关联工作区的会话显示“未归属”，可附原目录，不虚构名为“未分组”的工作区。
- 普通组的会话工作区选择器只生成当前组的项目。键盘与鼠标使用同一份项目数据；没有隐藏但仍可选中的其他组按钮。“未归属”中不提供工作区选择、添加或新建入口，包括快捷键触发路径。
- 拖拽排序只操作本组可见成员，合并写回时保留其他组在全局顺序中的相对顺序；“未归属”只有会话排序，不存在工作区排序或工作区拖入操作。各组的展开、平铺排序等本地状态使用带组编号的键。

从档案等全局入口打开其他组会话后，按第 6 节自动切组。

`allow` 的含义保持不变：未声明的插件在每组可用；声明后的页面按会话组收起或显示，工具由其宿主执行入口依据 `groupForSession(sessionId)` 校验。没有主会话时页面使用已选组。导航期间不能凭目标组提前改变旧会话的工具判断，后台运行会话也不受侧栏切组影响。

“未归属”使用稳定编号 `unassigned` 参与可用范围判断：未声明范围的通用插件可用；只允许普通业务组的插件在这里不可用，插件需要支持这里时显式把 `unassigned` 加入 allow。工作区删除造成的实际归属变化会影响后续工具调用判断，单纯切换侧栏或查看会话不会。

本服务不会自动改写第三方工具的执行逻辑，也不按组重建模型工具名单；本项目受限工具必须接入执行前校验。

## 9. 会话归属、移除与默认工作区

会话当前组使用统一解析器，宿主和浏览器遵循同一套规则：

1. 工作区和成员快照尚未就绪时等待，不能把加载中当成“未归属”。
2. 在完整现存工作区的权威 `sessionIds` 中找到会话时，使用该工作区的唯一成员组；工作区存在但成员操作未完成时先协调该操作，不能直接归入“未归属”。
3. 快照已就绪且会话不在任何现存工作区会话账户中时，当前组为 `unassigned`。即使 cwd 对应某个历史目录，也不恢复它原来的显示组。
4. 本项目以外新增的工作区按普通组接纳规则处理；没有现存工作区的外部会话进入“未归属”。绑定目录只用于默认工作区和目录浏览起点，不凭目录前缀猜测组。

不为当前组新增会话到组的持久表。新会话和普通分叉的工作区关联由已有 dsh 能力完成；插件订阅工作区、会话及重连变化后重新投影。未归属会话的分叉若仍没有工作区关联，也进入“未归属”。子代理的功能判断继承父会话当前组，不作为顶层列表或自动恢复目标。

移除工作区由本项目宿主服务处理：确保目录归属已经持久化，再调用 `workspaceRegistry.delete`。成功后清除该成员的默认标记并刷新列表，原会话按最新权威账户进入“未归属”。原普通组的关注会话不再用于下次恢复，下次切回该组时按普通组导航规则回退。当前打开的会话变成未归属时保持该会话，侧栏自动切到“未归属”。删除失败则保留原列表和归属，不能提前迁移显示。

普通组默认工作区登记不存在时清理过期标记，再按组绑定目录恢复。对默认路径也执行真实目录唯一归属检查；若因绑定路径重复或软链接指向其他组目录而冲突，报告组配置冲突，不抢占归属。每个普通组最终保留一个有效默认工作区，`unassigned` 完全跳过这一逻辑。

同组重新添加历史目录时使用新返回的工作区编号，按第 5 节恢复能够验证的历史会话关联。只有重新出现在该工作区权威 `sessionIds` 中的会话才从“未归属”回到普通组；仅目录存在、仅保留历史成员行或仅查看会话都不改变显示归属。旧工作区编号不能继续作为有效默认或导航目标。

## 10. 接口与生命周期要求

接口均位于 `/console-api/workspace-groups` 下，沿用 `consoleSession.read` 登录检查。新增工作区添加、组内重命名、移除接口；扩展 focus 接口以接受会话编号，快照增加组类型、目录、派生会话组和每工作区关注信息。

focus 写入必须校验会话存在、可恢复且当前属于该组，并核对可空工作区编号；`unassigned` 的工作区编号必须为空。所有工作区创建、认领及默认初始化入口都拒绝以 `unassigned` 为目标，客户端隐藏按钮不能代替此校验。名称冲突、目录跨组冲突、组不可用、系统组禁止操作、目标消失等预期失败返回不同的稳定 code。

服务拥有操作队列、订阅和进行中的请求，插件卸载按“停止接收、等待已接收工作、释放资源”清理。所有路由、槽登记、DOM 节点、样式和监听由 Cordis effect 或 React 生命周期持有。组快照需在操作成功、工作区或会话变化及重连后同步，不能只在页面初次加载时获取一次。

## 11. 实施顺序

1. 先恢复并验证官方侧栏接入：根侧栏挂载、官方槽的数据与动作适配、已有快捷键请求、原工作区选择器回调与草稿处理。不得再以重写列表代替适配。
2. 按目标规则建立新表结构和唯一归属查询，补齐宿主添加、改名、移除与中断恢复，不实现旧版本数据迁移。
3. 实现统一会话归属、关注保存和导航协调器，接入档案及外部主会话变化。
4. 在原侧栏、原选择器和原对话框内接入分组规则，覆盖搜索、平铺、“未归属”系统组和原有行操作，移除旧 DOM 隐藏工作区段落的逻辑。
5. 执行第 4 节的测试前重置，验证历史清空，再完成规则、集成与浏览器验收，最后更新 `design.md` 的现状及 `issues.md` 的解决状态。

本文件变更本身不执行清理，也不宣称修复完成。执行正式测试时必须落实上述清理要求，不再另行询问是否允许删除已授权的测试历史。

## 12. 验收

使用 `node:test` 验证规则、宿主操作和导航状态；涉及持久化的约束在隔离测试数据库验证。浏览器验收覆盖真实挂载、键盘和交互路径，不能只凭规则测试通过认定界面已修复。

- 正式测试前会话、工作区、归属、关注和相关浏览器历史已清空；导入源不使旧记录复活；账号、配置和真实目录文件保持完整。
- 同目录同组复用；跨组添加返回所属组与导航目标，不产生工作区、空白会话或关注变化。
- 软链接、路径别名和并发跨组添加仍只能产生一份目录归属；创建失败及重启后能正确清理或完成预留。
- 冲突链接打开对应组及工作区；原工作区已移除时可进入所属组重新添加。
- 两组可用同名；同组新增或改名冲突被宿主拒绝，Enter 与按钮行为一致；实际请求经过本项目 rename 接口，不走官方全局改名 RPC，持久标题和重启后显示正确。
- 普通组切换恢复上次有效会话；组内换会话会更新记录；“未归属”恢复有效会话或显示空态，不创建默认工作区及空白会话。
- 从档案、搜索和刷新恢复打开其他组会话时自动切组；快速 A→B→A、延迟响应和导航失败不串组、不写错关注。
- 搜索开关、搜索快捷键、添加快捷键在换会话及插件重载后仍正常，不重放旧搜索请求，不重复登记。
- 官方侧栏的结构、图标、间距、搜索展开和菜单交互保持原样；唯一新增常驻控件是已有的组选择器。工作区模式、目录树、平铺、标题搜索与正文搜索均只显示本组结果，结果上限正确。
- 普通组选择器鼠标与方向键只能选择本组工作区；添加目标组固定，提交前取消不产生记录；提交中防重入，断线重试不重复创建；恢复会话不搬移或覆盖其他会话的草稿和附件。
- 普通组都没有“未分组”栏；“未归属”只收没有现存工作区关联的会话，不能把其他组工作区下的会话错误收进来。
- “未归属”没有工作区添加或创建入口；快捷键和直接 API 请求也不能为它创建、认领工作区，业务插件不能覆盖保留组编号。
- 移除登记后目录和会话保留，会话统一进入“未归属”，当前打开的会话触发侧栏跟随；重启后结果一致。同组重新添加且恢复权威关联后，会话才返回普通组。
- 普通组默认工作区丢失能恢复，不保留无效默认编号，不抢占其他组目录；“未归属”从不进入默认初始化。
- 从空数据创建新结构和默认工作区成功；重置流程可重复执行，清理范围及前后计数可核验；新结构不依赖旧版本数据兼容分支。
- 页面及受限工具按实际会话组判断；“未归属”中的通用功能可用，限定普通业务组的功能不可用。工作区删除或重新关联后判断跟随实际归属变化，查看行为不改写归属。
- 置顶、会话改名、分叉、归档与恢复、运行提示、拖拽排序、展开状态和中英文显示完成回归；插件卸载清理所有临时资源。
